# 찌르기 v23 — 당겼다 내딛는 창 찌르기

사용자가 평타 중 휘두르기는 괜찮지만 찌르기(`combat_thrust_rh_v20`)가 밋밋하다고 했고, 세 후보 중 **당겼다 내딛는 창 찌르기**를
골랐다. 시작 파일은 이 폴더의 `thrust_v23.blend`(입력 `run_arm_v21.blend`, SHA-256 `80e04f5e…`)이며 정확한 해시는
`runtime_contract.json`과 `reports/thrust_v23/build_validation.json`에 있다.

## 동작 (49키/24fps/2초 저작, 판정 25F = 0.5)

- 0–36%: 지팡이를 왼쪽 허리 앞으로 낮게 끌어당기며 손 사이로 뒤로 미끄러뜨린다(축 이동 -0.26→-0.34m). 가슴을 약 26° 비틀고
  체중을 뒤로 싣는다. 오른손이 지팡이 머리 쪽이라 뒷손(왼손)이 왼쪽 허리에 오는 왼쪽 장전이다.
- 36–50%: 오른발을 36cm 내딛고, 골반을 9cm 낮추며 앞으로 16° 숙이고, 가슴을 -14°로 풀며 두 손으로 축을 따라 찔러 넣는다.
  판정 순간 지팡이가 손 사이로 앞으로 미끄러져 기존 공격과 같은 +0.16m에서 가장 멀리 뻗는다. 오른손 축 위치는 v20보다 약 6cm 더 앞이고 지팡이 끝은
  거의 두 배 앞까지 나간다.
- 50–60% 버티기, 60–100% 발을 거두고 대기 자세로 돌아온다. 처음과 끝은 대기(`combat_idle_rh_v20` 1프레임)와 같다.

## 만든 방법

`tools/build_thrust_v23.py`(백그라운드 Blender 5.1). v18 저작 틀(골반·다리 IK, 두 손이 하나의 지팡이를 잡는 IK)을 오른손 우위
v20 대기 그립으로 바꿔 썼고, 팔은 v21과 같은 팔꿈치 경첩면·손목 회전 규칙을 쓴다. 치마 보조뼈는 v17 연속 추종, v11 충돌 보정,
가디건 맞춤을 그대로 거친다. 가디건 맞춤이 빌려 쓰던 감사 스크립트가 저장소에 없어 `tools/cardigan_fit_helpers_v23.py`로 같은 두
함수(가중치 스키닝 점, 충돌 표면 트리)를 다시 만들었다 — 원본과 바이트 동일함은 확인할 수 없다.

빌드 검사: 49프레임 모두 다리 IK 오차 0, 팔 IK 오차 6e-8m, 지팡이 도달 보정 0, 왼손 그립 오차 0, 손가락 역방향 굽힘 0. 기존
29개 메시·107개 기준 뼈·기존 동작 전부 해시 보존.

## 게임 연결

v21 파츠 GLB는 다시 내보내지 않았다(그 내보내기 스크립트가 저장소에 없음). `tools/export_thrust_v23.py`가 뼈대와 가장 작은
스킨 메시(`Outfit_Buttons_v7`, 스킨 정보를 싣기 위한 운반용)와 새 동작 하나만 `combat_thrust_rh_v23.glb`로 내보내고,
`player_visual.gd`가 불러올 때 이 동작을 캐릭터의 기존 애니메이션 라이브러리에 더한다. 트랙 경로가 본체와 같은
`PlayerRig_v7/Skeleton3D:<뼈>`라 그대로 같은 뼈대를 움직인다. 가져오기 설정은 본체와 같게 24fps, 불변 트랙 유지,
애니메이션 최적화·압축 끔(켜면 직선에 가까운 키를 지워 19프레임에서 손이 12.8mm 어긋났다).

Godot 대조: 49프레임 전부 오른손 그립점 오차 0.000001m, 지팡이 축 0.0003°, 축 이동 값 0. 대기 자세와의 시작/끝 뼈 오차
0.0000005m. `runtime_contract.json`의 `attack_thrust`와 `staff_slide_tracks`에 새 동작이 들어가며 게임 폴더 계약도 같은 내용으로
바꿨다. 이전 `combat_thrust_rh_v20`은 v21 파츠 안에 그대로 남아 있다.
