## 파일과 제작 구조

Blender 5.1.1 / live MCP 1.8 protocol 15의 안전 모드에서 작업했다. `FirearmMaterialV3_matchlock`, `FirearmMaterialV3_rifle`, `FirearmMaterialV3_shotgun`이 새 자산이고, `FirearmMaterialV3_Bake`는 같은 부품을 링크한 베이킹 장면이다. 이전 v1/v2 장면과 `before_material_live.blend` 사본은 보존했다. `M_FirearmV3_Source_*` 11개 재질 노드는 fake user로 남으며, 각 부품의 `surface_key`로 다시 연결할 수 있다.

세 총이 한 아틀라스를 공유한다. 색 1024px(sRGB), OpenGL 탄젠트 노멀 1024px(Non-Color), ORM 512px(Non-Color, R=AO/G=거칠기/B=금속), 발광 256px(sRGB). 베이킹 여백은 각각 8/8/4/2px이며 UV 아일랜드 사이 간격은 별도로 확보했다. 일반 표면과 발광 부품은 재질을 분리해 금속으로 발광 밉이 번지지 않게 했다. 각 부품은 한 표면만 쓴다.

`textures/`는 편집용 PNG다. `exports/*.glb`는 이미지까지 내장한 이식용 사본, `game/assets/weapons/firearm_material_v3/*.glb`는 공통 `textures/*.png`를 참조하는 게임용 GLB다. 게임에서는 세 총이 동일한 텍스처 리소스를 사용하는지 검사한다. RGBA8 전체 밉을 가정한 공통 맵 크기는 약 12.3MiB이며 실제 최고 GPU 메모리나 성능 측정값은 아니다.

제작 순서는 스크립트의 `prepare()` → 채널별 `bake_channel()` → `finish()`를 live MCP로 실행하고, `tools/package_firearm_material_assets_v3.py`로 텍스처 공유와 내보내기 노멀 보존을 적용하는 것이다. 저장 원본의 평면 n-gon은 유지한다. 내보낼 때만 원본의 정확한 loop triangle 배열로 임시 메시를 만들어 탄젠트를 계산한다. Blender의 임시 분할 노멀 재인코딩 차이는 이전 GLB의 대응 정점/분할 노멀로 복구하고 새 탄젠트를 직교화한다.

## 검증과 남은 범위

저장 Blender 원본과 GLB 재반입을 검사하며, 전체 공통 UV에 대해 실제 삼각형 교차 면적을 검사한다. 기존 방아쇠 울의 UV 겹침은 면별 차트로 수정했다. 게임 재질 검사는 색/노멀/ORM 연결·채널·공통 텍스처 리소스·부품과 탄젠트·실제 조립 재질 보존을 다룬다. 기존 화승총/장총/산탄총 회귀 검사와 실제 게임의 조립·사격을 native 1.75x 및 확대 카메라에서 촬영한다. 완료 수치와 파일 해시는 전달 명세를 기준으로 한다.

기존 평면 캡 n-gon, 공중 총구 원점의 음수 높이, 독립 부품의 숨은 반대 방향 접합면, GLB UV/노멀 경계의 중복 정점은 의도적으로 유지한다. 내보내기 샘플러 재사용 경고는 동일한 선형/반복 이미지 설정을 두 재질이 공유하기 때문이다. 환경의 사용자 경로/셰이더 캐시/리뷰 종료 진단은 로그에 남긴다.

마모는 고정된 표면 표현이다. 실시간 손상·전 방향 캐릭터/벽 접촉·최종 성능 또는 새 재질의 사용자 승인을 뜻하지 않는다.
