# 기본 지팡이 · 공구 조립 v1

2026-10-29 사용자가 선택한 **낡은 황동·남색 자루 + 작은 청록 동력 코어** 방향으로 만든 시험판 후보다. 외형의 최종 승인은 아직 없다. 원본 하드서피스 메시를 Blender에서 직접 만들었으며 Tripo 생성물로 표기하지 않는다.

- 시작 파일: `authoring/staff_transform_v1.blend`. 다섯 그룹은 같은 결합 좌표에 있으며 `common`과 필요한 공구 그룹 하나를 함께 표시한다.
- 실제 게임 GLB: `exports/staff_parts.glb`와 `game/assets/weapons/staff_transform_v1/staff_parts.glb`는 동일 바이트다.
- 부품/피벗/조립 순서/장식 부착 지점: `parts.json`.
- 실제 게임 리뷰: `reports/staff_transform_v1/review.html`; 검사와 현재 파일 해시는 `delivery_manifest.json`.

## 기존 모션과의 계약

- 기존 `run_arm_v21` 캐릭터 GLB, 107본, 바인드, 클립과 양손 동작은 변경하지 않았다.
- `DEF-hand.R`, `STAFF_GRIP_OFFSET`, `STAFF_GRIP_BASIS`, 원래 지팡이 슬라이드 트랙, 1.5/1.711 런타임 배율을 그대로 사용한다.
- 자루 축은 로컬 +Y. 지름 20mm 자루 위의 얇은 그립은 반경 10.8mm다. 실제 가져온 정점에서 손이 움직이는 구간의 반경을 검사한다. 굵은 공구/장식은 손잡이 위에 놓인다.
- 기존 모션에서 지팡이를 드는 축 자체는 같다. 큰 헤드가 모든 중간 자세·옷·몸과 무관통이라는 검증은 하지 않았다.

## 공구 변환

`game/scripts/staff_visual.gd`가 표현을 소유하고 `player_visual.gd`가 기존 전투 상태로 갱신한다. `arena.gd`와 피해·마나·공격/이동 시간 규칙은 이 작업에서 편집하지 않았다.

- 공통 자루·코어는 유지한다. 공구 부품은 약 0.22초 동안 생성되어 각자 피벗으로 결합한다. 청록 입자와 얇은 주사 고리를 쓴다.
- 다른 공구로 바꾸거나 해제하면 기존 부품이 약 0.16초 동안 빠져나가며 작아져 소멸한다. 빠르게 재전환하면 그 순간 부품의 진행률에서 이어간다.
- 논리 공구 그룹은 즉시 전환하고 빠지는 실제 메시만 `DepartingToolParts`로 옮긴다. 마나 소진 시 잔상은 공격 가능한 공구가 아니다.
- 기존 공구 전환은 **즉시 토글**이다. 새 시전 시간·정지 시간·마나 비용을 만들지 않는다. 피격 경직은 공구 토글을 취소하지 않으며, 기존 상태를 따라 조립이 진행된다.
- 극단적으로 빠른 공격은 실제 타격 시점까지 공구가 준비되도록 표현만 앞당긴다. 기존 0.5 타격 자세를 유지한다.
- 집게는 타격 동작에 맞춰 닫히고, 원판과 기어는 독립 회전하며, 톱니는 가이드 바의 캡슐 경로를 돈다. 전역/전투 RNG를 쓰지 않는다.
- 일시정지는 조립·회전·입자를 함께 멈춘다. 사망·클리어도 동결한다. 아레나 초기화는 지팡이와 효과를 함께 제거한다.
- 기존 `tool_changed` 기계음과 음소거를 그대로 사용한다.

## 장비 외형 확장 계획

장비 규칙 원본은 `docs/04_items.md` §3.3이다. **공구는 스킬 상태**, **장식은 매개체 외형 프로필**로 분리한다.

현재 `player_visual.set_staff_appearance("basic" | "seal")`로 독립 교체한다. 잘못된 프로필은 기존 외형을 유지한다. `seal`은 데이터 계약 확인용 예제이며 실제 아이템이나 성능을 뜻하지 않는다. 코어 아래 정면 부착부와 좌우 예약 지점은 `parts.json`에 있다. 장비 UI와 아이템 데이터 연결은 이번 범위가 아니다.

후속 장식은 다음 조건을 따른다.

1. 같은 기본 지팡이와 손잡이 계약을 유지한다. 장식 프로필에서 공구 활성 상태나 공격 수치를 바꾸지 않는다.
2. 공용 장식 베이스를 우선 재사용하고, 일부 고유 매개체에만 전용 장식을 만든다.
3. 기본 부착부의 허용 크기 안에서 만들고, 세 공구의 결합·회전 경로 및 양손 슬라이드 구간을 침범하지 않게 한다.
4. 더 큰 도면 두루마리·기어·결정·리본은 별도 지점/크기 계약과 실제 동작 검토를 거친다. 물리 천·흔들리는 체인은 아직 없다.
5. 모든 아이템의 고유 모델, UI, 장비 드롭이나 통계 규칙을 이 아트 계약에 넣지 않는다.

## 재생성·검증

`tools/build_staff_transform_v1.py`는 별도 Blender background 프로세스용이다. 열린 사용자 Blender에서 실행하면 장면을 초기화하므로 실행하지 않는다. 본 작업 당시 MCP가 연결되지 않아 background Blender 5.1.1을 사용했다.

`tools/run_staff_transform_v1.ps1 -Phase import`, `-Phase test -Test staff_visual`, `-Phase review`로 Godot 4.6.2에서 확인한다. 입력 파일 스냅샷과 전후 해시를 각 검사 폴더에 보관한다. 기본 공구 회귀, 캐릭터 모션/두 공격, 피격, 입력 유지도 함께 기록한다. `tools/package_staff_transform_v1.py`는 실제 캡처와 검사 결과만 패키징한다.

이 후보는 최종 외형·플레이 감각·성능 예산·임의 자세의 접촉 승인이 아니다.
