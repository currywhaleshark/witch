# 스프링 돌진 · 바닥 발판 v1

사용자가 요청한 **바닥 스프링판 조립 → 작동 → 소멸**을 기존 `spring_dash`에 연결했다. 발판과 도약은 v24 검토 후 선택되었다. **2026-11-01 후속 수정:** 도착 뒤에도 발판이 보이도록 유지 시간을 늘렸다. 현재 타이밍은 [유지 시간 검토](../../../reports/spring_plate_hold/review.html)와 해당 폴더의 검증 기록을 따른다. [최초 게임 화면](../../../reports/spring_dash_v1/review.html)과 [v1 검증·해시](../../../reports/spring_dash_v1/delivery_manifest.json)는 변경 전 기록이다.

## 파일

- `authoring/spring_plate.blend`: Blender 5.1.1에서 직접 제작한 원본. Tripo 생성물이나 기존 모델의 추출물이 아니다.
- `exports/spring_plate.glb`: 정적 독립 메시 29개, 재질 6개, 5,964삼각형. 뼈·애니메이션·텍스처는 없다.
- `parts.json`: 조립 순서, 부품 역할, 코일 치수와 작동 시간.
- `../../../game/assets/props/spring_dash_v1/`: 같은 GLB와 설정의 게임용 사본.
- `../../../game/scripts/spring_plate.gd`: 기존 `summon_assembly.gd`를 상속하는 시각 연출.
- `../../../game/scripts/arena.gd`: 실제 발동·취소에 연결하는 좁은 변경. 스프링 돌진 자체의 규칙은 앞서 추가된 구현을 그대로 따른다.

남색 발판·황동 프레임·강철 코일·고무 디딤면·작은 청록 표식을 사용했다. 단순 PBR 재질이며 마모 지도는 별도 제작하지 않았다. 닫힌 외곽은 약 0.65 × 0.82m, 디딤면 높이는 약 0.147m다. 현재 조립 원점은 출발 위치에서 돌진 방향의 반대쪽으로 0.16m 옮긴 지면이다.

## 연결과 동작

기존 시전의 발동 시각까지 조립한다. FCR 0은 0.06초, FCR 40은 약 0.037846초이며 프레임 단위 실행에서는 다음 시뮬레이션 프레임에 발동한다. 연출 때문에 대기 시간을 추가하지 않는다. 게임의 S 스킬창에서 슬롯에 배치하며 리뷰는 Q를 사용한다.

실제 `start_dash()`가 호출되면 한 번만 작동한다. 발판이 0.085초 동안 최대 0.185m 상승하며 전방으로 9도 기울고, 걸쇠가 벌어진다. 완전히 펼쳐진 채 0.55초 유지한 뒤 0.24초 동안 부품이 살짝 흩어지며 사라진다. 소멸 시작은 발동 후 0.635초, 총 수명은 0.875초다. 현재 0.2초 돌진 기준으로 도착 후 약 0.435초, 0.12초 착지 자세까지 끝난 뒤 약 0.315초 동안 더 보인다. 실제 프레임 경계에서 한 프레임 정도 차이가 날 수 있으며 벽에 일찍 멈추면 도착 후 더 오래 남는다. 장치는 출발 지점에 남고 플레이어를 따라가지 않는다. 돌진 시간·이동 거리·조립·취소 연출은 그대로다.

두 코일은 철선 굵기를 축척하지 않고 나선 간격만 바꿔 압축·신장을 표현한다. 런타임 끝마개 차이로 두 코일 합계 8삼각형이 추가되어 **장치 메시 합계는 5,972삼각형**이다. 이는 주변 빛·모트 등 전체 렌더 비용을 뜻하지 않는다. 코일 메시 하나를 두 부품이 공유한다. 가이드는 하부 슬리브·절반 거리로 이동하는 중간 관·상부 봉으로 나눴다.

발동 전 큰 피격/사망/유효성 재검사 실패로 취소되면 그때 보이는 부품만 현재 자세에서 소멸하고, 압축을 해제하지 않는다. 마나·슬롯 유효성은 기존처럼 실제 발동 시점에 재검사한다. 취소가 확정되기 전의 조립은 계속될 수 있다. 소모/쿨다운/거리/충돌/경직 규칙은 arena가 소유한다. 작은 피격은 기존대로 시전을 유지한다. 일시정지는 연출도 멈추고 초기화·맵 이동은 모든 장치를 제거한다.

기존 `mechanical_impact.wav`를 성공한 발동당 한 번, 피치 1.65/실효 -19dB로 재사용한다. 기존 음소거와 음성 풀을 따른다. 새 오디오 생성이나 별도 청취 검토는 하지 않았다. 리뷰 캡처는 무음이다.

## v1 최초 검증 (유지 시간 변경 전)

- 저장 Blender 재열기 및 GLB: 29개 메시/6재질/5,964삼각형, 유한 좌표, 피벗·동일 게임 사본 검사.
- 신규 `spring_plate_v1`: **82개**. 30/60fps × FCR 0/40, 기존 발동·소모·쿨다운·돌진, 완성된 압축 자세에서 발동, 출발 지점 유지, 취소·정지·맵/초기화 제거, 다중 장치, 높은 바닥, 음소거/발동음.
- 기존 `loadout_dash` 11개와 `hit_block` 20개: **합계 113개**, 실패 0.
- 출발점 오차 0m, 측정한 코일 철선 반지름 오차 최대 약 0.0000201mm, 작동 중 가이드 연결부 최소 겹침 약 12.5mm.
- 실제 Godot 4.6.2 GPU 렌더 **487장**. 기구 확대만 240Hz 샘플·추가 조명, 게임 여섯 장면은 60Hz·기존 조명이다. 캡처는 렌더 시간 차이를 배제하려고 프레임마다 시뮬레이션을 수동 진행하지만 실제 arena 발동/이동/소모 경로를 사용한다.
- 렌더·검사 전후 입력 해시 일치, 종료 코드 0. GPU의 알려진 `user://` 셰이더 캐시 폴더 진단은 로그에 그대로 기록했다. HTML 자바스크립트 문법·모든 이미지 크기/무결성을 확인했으며 브라우저 조작 자동검사는 하지 않았다.

## 보존 범위와 제한

작업 시작 당시의 변경사항은 `reports/spring_dash_v1/baseline/`에 보존했다. [정확한 arena 차이](../../../reports/spring_dash_v1/integration.diff)와 [범위 검사](../../../reports/spring_dash_v1/integration_scope.json)를 참조한다. `player_visual.gd`, `summon_assembly.gd`, `hud.gd`는 시작본과 바이트가 같다. 스프링 돌진 설정도 같다. 동시에 진행된 공구 유지비 5→2 변경은 그대로 보존했으며 최종 검사 입력에 포함된다. 다른 작업자의 빌드/스킬창·성장 변경을 이 연출의 작업으로 간주하지 않는다.

이 장치는 시각 효과이며 플레이어를 실제 물리 스프링으로 밀거나 발판에 발을 고정하지 않는다. 기존 캐릭터 시전/돌진 모션을 사용한다. 평지와 1.2m 높은 지면은 검사했으나 임의 절벽·단차에서 발판 전체가 바닥에 지지되는지, 부품간 충돌이나 최종 성능 예산은 검증하지 않았다.

## 재현

원본 빌드는 `tools/build_spring_dash_v1.py`, 저장 파일 검사는 `tools/validate_spring_dash_source_v1.py`를 백그라운드 Blender에서 실행한다. 사용자 Blender 세션에 직접 실행하지 않는다.

저장소 루트에서:

```powershell
& tools/run_spring_dash_v1.ps1 -Phase import
& tools/run_spring_dash_v1.ps1 -Test spring_plate_v1
& tools/run_spring_dash_v1.ps1 -Test loadout_dash
& tools/run_spring_dash_v1.ps1 -Test hit_block
& tools/run_spring_dash_v1.ps1 -Phase review
python tools/package_spring_dash_v1.py
```

패키징은 검사 당시 입력이 현재 파일과 다르면 실패한다. 다른 작업자가 코드를 바꾼 뒤라면 영향받은 검사를 먼저 다시 수행해야 한다.
