# 기계 수렵견 — 기본형·강체 모션 v2

2026-11-05. 사용자가 원화와 Tripo 원본 방향을 받아들이고 후속 작업을 요청했다. [검토 페이지](../../../../reports/hound_game_v2/review.html)에서 6개 동작, 각도별 형태, 부품·와이어, 기존 배우들과의 실제 카메라 크기를 확인할 수 있다.

## 현재 파일

- `hound_game_v2.blend`: 이미지가 packed된 편집 원본. 1 메시, **6,795 삼각형 / 33 강체 그룹 / 37 본 / 2 재질 / 6 액션**. 열면 대기 동작이 선택되어 있고 재생할 수 있다. 액션 이름은 아래 표와 같다. 각 액션의 NLA 트랙은 개별 편집·선택을 위해 음소거 상태로 보관했다. 본 편집 때는 뷰포트 오버레이를 켠다.
- `hound_geometry.blend`: 리그를 붙이기 전 경량화·베이크 결과.
- `hound_v2.glb`: 모든 클립과 스킨을 담은 내보내기 결과. 게임 폴더의 같은 파일과 바이트가 같다.
- `parts.json`: 강체 그룹, 부모·피벗, 소켓, 그림자 반경, 클립 길이·키 시간, 사냥 무리 크기 계약.
- `geometry.json`, `rig.json`, `production.json`: 원본 파트 대응, 정적 피팅, 수정 면, 피스톤 스트로크, 검증 범위와 제한.
- 게임 전달 폴더: `game/assets/actors/automation_batch2/hound_v2/`. **GLB·parts.json·임포트 설정·import_exact_animation.gd를 함께 복사한다.**

이 자산은 **준비된 아트와 동작 시안**이다. 현재 `actor_visual.gd`의 배우 목록이나 스킬 규칙에는 추가하지 않았다. 신호기와 거대 자동인형은 이전 원화 단계 그대로다. 중장 추적기의 추가 머리·어깨 장갑과 톱날 턱은 후속 작업이다.

## 원본에서 달라진 것

[v1 작업용 원본](../hound_tripo_v1/README.md)의 60 조각 / 76,862 삼각형을 실제 구동 단위 33개로 재구성했다. 목과 턱이 섞인 파트 36, 뒷다리의 두 마디가 붙은 파트 28을 나누고, 흉곽·목·머리·발의 장식 조각은 해당 강체 그룹에 묶었다. 기존 통짜 피스톤은 독립 실린더·막대와 연결 핀으로 교체했다. 다리의 열린 분할 경계에는 안쪽 마감 면을 만들고 회전축을 보강했다. 소스 두 GLB와 v1 원본·작업용 blend는 변경하지 않았다.

미터 크기와 방향은 리깅 전에 정점에 적용했다. 원점은 네 발 받침 중심의 평균과 바닥이다. Blender +Y가 앞이며 GLB/Godot에서는 **−Z가 앞, Y가 위**다. 코끝~골반 뒤 약 **0.955m**, 어깨 껍질 높이 **0.497m**, 안테나를 제외한 머리 윗면 **0.628m**다. 전체 길이는 꼬리와 벌어진 발 때문에 이보다 크다. 정적 피팅 행렬과 목의 −7도 조정은 `geometry.json`에 있다.

각 정점은 본 하나에 100% 붙고 한 삼각형이 두 강체 본에 걸치지 않는다. 부품들이 하나의 메시·두 표면에 들어 있으므로 해체/조립 사본이 필요할 때는 본별 정점 그룹으로 분리할 수 있다. 재질은 공통 1K 색 / OpenGL 노멀 / ORM, 64px 발광이다. ORM의 R은 중립값 1이며 별도 AO 베이크를 주장하지 않는다. 렌즈와 꼬리 끝 발광 면은 별도 재질이다.

피스톤의 원통과 막대는 고정 길이이며 키를 따라 회전·슬라이드한다. 모든 원본 동작을 촘촘히 샘플링해 스트로크 길이를 계산한 뒤, 한 번만 정지 메시 길이를 맞췄다. 최소 겹침 12mm와 막대 뒷단 여유 6mm를 두었다. 이 길이 보정은 애니메이션 스케일이 아니다. 피스톤 표면의 기존 UV는 이 정적 길이 보정에 따라 길이 방향으로 약간 변한다.

## 동작과 가져오기

| 액션 | 길이 | 계약 |
|---|---:|---|
| `spawn` | 0.4초 | 웅크림 → 기립 |
| `idle` | 1초, 루프 | 가슴·열쇠·꼬리 움직임 |
| `run` | 0.5초, 루프 | 네 다리 질주, 제자리 클립. 기준 속도 6.5m/s, 주기 거리 **3.25m** |
| `bite` | 0.6초 | 준비 후 전진하는 몸짓, **0.3초에 턱 닫힘** |
| `hit` | 0.25초 | 짧은 피격 반응 |
| `death` | 1.2초 | 폭발 없이 부품이 흩어져 낙하·정착 |

씬 타임라인과 기본 키는 24fps다. 0.4/0.6/1.2초 끝점과 0.3초 타격점은 정수 프레임으로 반올림하지 않는다. 달리기의 짧은 접지 구간에는 추가 subframe 키가 있다. 키 시간 전체는 `parts.json`에 저장했다.

Godot 기본 GLTF 가져오기는 최적화를 꺼도 접지 키를 정수 프레임으로 다시 샘플링했다. 이때 실제 검사에서 발이 바닥 아래로 내려갔다. 전용 `EditorScenePostImport`가 GLB의 위치·쿼터니언·스케일 키를 그대로 AnimationLibrary에 복원한다. **실행 중 보정 코드가 아니라 이 자산의 임포트 처리**다. 기존 배우·프로젝트 설정에는 영향을 주지 않는다. `animation/fps=24`, 상수 트랙 유지, AnimationPlayer 최적화·압축 비활성화도 함께 설정했다. [Godot 공식 임포트 스크립트 문서](https://docs.godotengine.org/en/stable/classes/class_editorscenepostimport.html).

소켓은 `Socket_attack`, `Socket_core`, `Socket_bar`다. 사냥 무리 검토는 같은 메시·텍스처를 0.8배로 세 번 사용한다. 별도 모델이나 기본 정점 변경은 없다. 중장 추적기는 아직 제공하지 않는다.

## 검증과 한계

- 저장본 재열기 142개 자세, 6개 액션과 루프 양 끝, 단일 본 가중치, 강체 변환, 새 GLB 재임포트를 확인했다. 저장본·재임포트 메시 QA 오류는 모두 0개다.
- 실제 Godot 검사 **36,509개**, GPU 캡처 **312장**. 약 240Hz 간격으로 각 클립의 회전된 실제 정점 바닥 높이를 검사했다. 가장 낮은 값도 바닥 위 약 0.52mm였다. 이는 기록한 평평한 바닥·클립 범위의 결과다.
- 모든 제작 키에서 Blender와 Godot 본 원점도 비교한다. 정확한 최대 오차와 입력 해시는 `reports/hound_game_v2/validation/runtime_parity.json`, `delivery_manifest.json`에 있다.
- 남은 메시 경고는 접합/UV 경계의 일치 정점 22개와 숨겨진 반대 방향 접합면 2쌍이다. 몸통 원본 쉘의 열린 경계와 관절 안쪽 겹침도 유지한다. 전체 부품 간 충돌·완전한 폐곡면 인증이 아니다.
- 붕괴는 제작된 대기 자세에서 시작하는 낙하 시안이다. 임의 동작 중 파괴 전환, 지형·벽·부품 간 실시간 충돌과 최종 성능은 별도 연결 작업이다.
- 크기 비교는 현재 캐릭터·소환물·적 자산과 실제 1.75배 카메라 설정을 사용하는 Godot 캡처다. 동일한 검토 조명을 사용했고 본 게임 조명은 수정하지 않았다.

라이브 MCP는 연결되지 않아 설치된 Blender 5.1.1의 별도 background 프로세스로 작업했다. 썸네일 폴더·Godot user:// 쓰기 진단은 로컬 환경 기록으로 남겼으며, 파일 저장·임포트·검사·GPU 렌더는 성공했다. 추가 Tripo 생성·크레딧 사용은 없다.

## 재생성

Blender 5.1.1 background에서 `tools/build_hound_game_v2.py` → `tools/animate_hound_game_v2.py`, 일반 Python에서 `tools/export_hound_game_v2.py` 순서다. `tools/validate_hound_game_v2.py`는 Blender 검증, `game/tests/review_hound_game_v2.gd`는 Godot 검사·캡처, `tools/package_hound_game_v2.py`는 영상·검토 페이지·명세를 만든다. 빌드에는 v1 packed 작업용 원본이 필요하다. 원본 로그·부품 진단과 전체 캡처 프레임은 로컬 보조 자료이며, 배포 검토는 MP4·대표 이미지로 가능하다.
