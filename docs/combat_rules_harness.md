# 엔진 독립 전투 규칙 검증

> 2026-10-25 · 전투 입력·마나·공구 상태의 실행 가능한 Python 참조 구현. 이 모듈 자체에는 화면이 없으며, 후속 [Godot 4.6 전투 시안](godot_prototype.md)이 동일 시나리오를 재생하는 별도 GDScript 이식을 포함한다. 규칙의 원본은 [02](02_combat.md), 검증 기준은 [06 단계 A](06_vertical_slice.md)다.

## 실행과 확인 결과

Python 3.10 이상에서 프로젝트 루트 기준으로 실행한다. 전투 검증 자체는 표준 라이브러리만 사용한다. 전체 테스트의 기존 이미지 검사는 `tools/requirements.txt`의 Pillow가 필요하다.

```powershell
python -m combat_rules --report reports/combat_rules_report.json
python -m unittest discover -s tests -v
```

시나리오 실행은 성공 `0`, 기대 결과 불일치 `1`, 잘못된 설정/실행 오류 `2`로 종료한다. 출력 보고서는 명령으로 지정한 경로에 생성한다.

**실행 결과:** 재생 시나리오 13개·39단계 통과(2026-10-26 설치 불가 지면 단계 추가). 전투 테스트 28개와 기존 자산 테스트 15개를 합한 43개 통과. 테스트에는 잘못된 기대 결과가 실제로 실패 코드와 보고서를 만드는지도 포함한다.

| 파일 | 역할 |
|---|---|

## 엔진에 연결할 경계

`CombatRules`는 엔진 객체를 받지 않는다. 입력 상태를 수정하지 않고 `Transition(state, events)`를 돌려준다. 호출자가 반환한 상태를 다음 호출에 전달한다.

| 함수/값 | 호출자와의 계약 |
|---|---|
| `initial_state(max_mana, mana)` | 최대/현재 마나를 명시하고 초기 상태 생성. 처음 좌클릭에는 기본 공격 장착 |
| `bind(state, slot, skill_id)` | 시험용 슬롯 등록. 장비/스킬 편집 UI나 전투 중 재배치 허용 규칙은 구현하지 않음 |
| `Cursor(enemy_id, ground)` | **키를 누른 순간**의 유효 적 ID와 유효 지면 좌표를 고정해 전달. 레이캐스트는 엔진 책임 |
| `press(state, slot, cursor, spatial_check=..., shift=False)` | 키 누름 한 번을 처리. 별도 확정 클릭·지연 시전 대기열·키 유지 반복은 없음 |
| `spatial_check(skill, cursor)` | 필수 어댑터. 선택 기술의 사거리/설치 가능 여부를 검사해 `None`, `out_of_range`, `invalid_ground` 반환. 대체 기본 공격도 **다시** 검사 |
| `advance(state, seconds)` | 경과 시간만큼 공구 유지비와 쿨다운 처리. 실제 이동/피해/마나 자연회복을 실행하지 않음 |
| `restore_mana(state, amount)` | 외부에서 공급한 회복량을 적용. 물약/장비/패시브/회복 속도를 정의하지 않음 |

지면 좌표는 엔진의 3차원 월드 좌표이며 이 단계에서는 거리 계산이나 좌표축/단위를 고정하지 않는다. 이동 요청은 목적지만 반환하므로 길찾기·도달 가능성도 엔진에서 처리한다.

`cast`는 **시전 허가 및 적용 요청**이지 피해 적용 완료가 아니다. `origin`은 `player`, `player_adjacent`, `cursor_ground` 중 하나이며, 소환 위치의 정확한 오프셋·충돌·생존 시간·AI는 소비자가 처리해야 한다. `active_tool`을 기본 공격의 모션/효과 선택에 사용할 수 있으나 공구별 피해·상태이상은 여기서 계산하지 않는다.

숫자 1~4는 `input_ignored/outside_active_slots`로 반환한다. 엔진 입력 어댑터가 별도 물약 시스템에 전달할 수 있으며, 이 모듈에는 물약 기능이나 숨겨진 액티브 슬롯이 없다.

## 확정 규칙과 시험 선택 구분

확정 규칙의 설명을 이 문서에서 다시 정의하지 않는다. [02 §1~§3](02_combat.md)을 적용한 결과를 [06](06_vertical_slice.md)의 A1~A5와 연결해 검증한다.

다음은 **현재 검증을 실행하기 위해 선택한 임시 정책**이다. JSON의 `status`는 `test_values_not_approved_balance`이며 `trial_*` 기술은 입력 유형을 시험하는 가짜 카탈로그 ID다. 새 스킬 설계나 실제 스킬의 밸런스 수치로 해석하지 않는다.

| 미결 지점 | 현재 시험 선택 |
|---|---|
| 실패 사유가 여러 개인 경우 | `target → spatial → cooldown → mana` 순서. `TrialPolicy.failure_order`로 순서 변경 가능하며 순서가 바뀌는 사례도 검사 |
| 대상/지면/사거리/쿨다운 실패 | 이동이나 대체 공격 없이 실패 이벤트. 이 정책만 현재 구현됨 |
| 같은 공구를 수동 해제할 때 비용/쿨다운 검사 | 무료 해제를 먼저 처리. 이 정책만 현재 구현됨 |
| 시전 비용과 0마나 자동 해제 순서 | 비용과 시전 이벤트 적용 후 0마나 공구 해제. 0마나에서 비용 0 공구를 눌러도 같은 전이에서 즉시 해제되므로 활성 상태는 남지 않음 |
| 마나·유지비·시전 비용·쿨다운 | 모두 JSON의 시험값. 쿨다운은 이 참조 구현에서 기술 ID별로 공유하며 슬롯 재등록으로 초기화하지 않음 |
| 회복 | 자동 회복을 가정하지 않고 명시적인 `restore_mana` 호출로만 공급 |
| 같은 시점의 유지비/입력/회복 | 시나리오에 기록된 호출 순서를 그대로 적용. 엔진의 프레임 처리 순서는 아직 정하지 않음 |

미구현 정책 이름을 넘기면 오류로 종료한다. 승인된 동작인 것처럼 조용히 다른 처리로 바꾸지 않는다. `Decimal` 시간/마나로 분할된 유지비 계산의 경계 오차를 줄였으며, 0.1초 10회와 1초 1회가 같은 고갈 상태로 끝나는지 검사했다. 이는 최종 엔진의 수치 표현 방식을 확정하지 않는다.

## Python 모듈만으로 검증하는 범위

**접근 후 시전 연결:** Python과 GDScript의 이 모듈은 **현재 위치에서 단일 시전이 가능한지** 검사하므로 공간 어댑터가 보고한 `out_of_range`를 그대로 반환한다. 사용자가 요청한 [접근 후 시전](02_combat.md)은 Godot 이동 계층의 보류 요청·추적·재검사로 구현한다. 기존 JSON 13개 시나리오는 단일 시전 계약을 그대로 재사용하며, 접근 동작은 별도 [씬 검사](../game/tests/approach_cast.gd)로 검증한다. 모듈의 `reject_without_moving`은 게임 전체가 이동하지 않는다는 뜻이 아니다.

- A1/A2: 입력 분기·시전 요청은 자동 확인. 실제 마우스 피킹·애니메이션·조작 체감은 미검증.
- A3: 생성 기준 위치/초기 표적을 담은 요청은 확인. 실제 소환체 생성·충돌·자율행동은 미구현.
- A4/A5: 자원/공구 전이와 실패·복귀 이벤트는 확인. 마나 고갈의 불편감, 실패 UI, 사망·지역 전환 정책은 미검증.
- HP·적의 추격/공격·공간 타격·피해·출혈·전투 밸런스·완성 아트는 이 작업 범위에 포함하지 않았다.

후속 Godot 시안에서 피킹·공간 판정·이동·공격·HP/MP를 연결했다. 실제 씬 검사와 남은 한계는 [Godot 실행 안내](godot_prototype.md)를 참조한다. Python 모듈의 범위와 게임 전체 구현 상태를 구분하며, 엔진 독립 규칙 통과를 P0 완성 또는 A1~A5의 전체 플레이 검증 완료로 표시하지 않는다.
