# 첫 시험판(버티컬 슬라이스) — 검증 계획

> **현행 v0.3 · 2026-10-25.** **[사용자 승인] 최소 시안은 시나리오·거점 없이 전투 필드 자체를 구현**하는 데 집중한다. 이 문서는 무엇을 검증하고 어떤 결과를 기록할지만 정의하며 스킬·피해 공식·입력 규칙을 복제하지 않는다.

## 0. 최초 최소 시안 — 전투 필드만 [합의된 범위]

**목표:** **서사 없이 기계장치의 마녀 한 명을 움직여 적과 싸울 수 있는 전투 필드**를 먼저 만든다. 우선순위는 **이동과 커서 지정 시전 → 공격/피격 판정 → 적의 간단한 이동·추격·공격 → HP/MP와 기본 UI → 대표 스킬 동작** 순으로 잡는다. 현재 실행 환경과 시험 설정은 [Godot 시안 안내](godot_prototype.md)를 따른다.

**포함 가안:** 임시 그래픽/도형으로 구성된 필드 1개, 기계장치의 마녀 1종, 적 1~2종, 기본 공격과 대표적인 화기/구동/자동화 스킬 최소 예시, HP·MP 및 피격/사망 피드백. **제작 대상은 기능 확인에 충분한 최소량**으로 제한한다.

**이번에는 하지 않음:** 프롤로그, 4막 서사, 퀘스트와 대사, 동사무소 허브, NPC, 이벤트 컷신, **SCG 편집·커스터마이징 UI**, 다른 두 클래스의 모델링/스킬 전면 구현, 장비 제작·완전한 인벤토리·파밍 경제. 이런 것들은 처음 전투 필드가 작동한 뒤 따로 확장한다.

**[제작 사양 분리]** 2D SCG·Tripo 3D 아트·외형 설정 JSON과 원화 인계는 [09 · 캐릭터 아트 문서](09_character_art_pipeline.md)의 범위다. 이 시험판에서 대화 SCG 구현을 완료 조건으로 요구하지 않는다.

**1차 완료 기준:** 한 필드에서 이동·적 선택·공격·피격과 적의 대응이 가능하며, 우클릭·QWER와 Shift+좌클릭을 사용해 기술을 안정적으로 시전할 수 있다. 공구 토글의 마나 고갈과 소환/설치도 작은 테스트로 확인한다. **C단계 파밍 루프는 이후 확장 검증이지 최초 시안의 완성 조건이 아니다.**

## 1. 우선 검증할 가설

1. **조작:** 클릭 이동과 6개 액티브, 이동형 소환과 지면 설치를 입력 충돌 없이 다룰 수 있는가?
2. **마나 흐름:** 공구 토글 중 마나가 바닥나도 스킬 사용과 전투 복귀가 지나치게 답답하지 않은가?
3. **성장 선택:** 화기·구동·자동화의 손맛이 달라지고, 스킬 랭크 집중과 선택적 A/B 특화가 모두 경쟁력이 있는가?
4. **피해 판정:** 명중·치명·출혈의 계산이 의도대로 작동하며, 보스에게 출혈이 과도하게 강하거나 무용지물이 되지 않는가?
5. **육성·파밍:** 무료 스킬/스탯 초기화와 아이템 옵션 교체가 실제로 다양한 빌드를 시도하게 만드는가?

## 2. 단계 A — 조작·자원 프로토타입 (가장 먼저)

**A단계 기능 가안:** 기계장치의 마녀 1명, 적 1~2종, 임시 전투 필드, 기본 공격과 산탄포·공구 변형·태엽인형·설치기 중 동작을 확인할 수 있는 일부. **최초 목표는 작동하는 전투**이지 모든 스킬의 구현이 아니다. 입력·상태 전이의 원본은 [02](02_combat.md), 스킬은 [03](03_skills.md).

**자동 검증 기록 (2026-10-25):** [엔진 독립 검증 코드](combat_rules_harness.md)와 [Godot 이식](godot_prototype.md)에서 A1~A5의 동일 입력 시나리오 13개·38단계를 실행했다. [Python 보고서](../reports/combat_rules_report.json), [Godot 보고서](../reports/godot_rules_report.json)를 보존한다. 추가로 물리 피킹·이동·피해·소환 위치·마나 고갈·사망/재시작을 [전투 씬 통합 검사](../reports/godot_smoke_report.json)로 확인하고 실제 렌더링을 검수했다. **사용자의 조작 체감·장기 고갈 불편감 및 모든 A항목의 수동 플레이 통과 판정은 아직 하지 않았다.** 수치와 미결 예외는 시험 설정이며 합의된 게임 규칙으로 확정하지 않는다.

**수동 플레이 기록 (2026-10-25):** 사용자가 Godot 시안(`07a7529`)을 직접 플레이하고 "조작감 괜찮다"고 판단했다. **A1·A2·A6·A7 조작감 통과.** 누르고 있기·고정 쿼터뷰 카메라·방향 지정 기술 즉시 시전을 반영한 상태다. A3(소환·설치 피드백), A4(공구 전환), A5(장기 마나 고갈)는 아직 수동 판정 전이다. 이 통과는 조작감에 대한 것이며 피해·마나·속도 수치의 밸런스 승인이 아니다. **A4 (2026-10-25):** 그라인더(R)를 추가한 시안에서 사용자가 볼트 커터↔그라인더 전환을 직접 플레이하고 "잘 작동한다"고 확인했다. 동작 확인이며 두 공구의 수치 균형 승인은 아니다. **물약 (2026-10-26):** 사용자가 물약 퀵슬롯을 직접 써 보고 종류별 쿨타임이 의도대로 돈다고 확인했다("괜찮은 듯"). 회복량은 나중에 다시 조정한다. 같은 날 A5 시험 모드 기록(`reports/playtest/a5_mana_20261026_004700_manual.json`, 마나 회복 4 MP/s, 교전 약 138초): 마나(중) 5개를 모두 쓰고 체력 2·회복 2·이동 속도 1개 사용, 기술 공백 4.3%(3회, 최장 2.4초), 마나 부족 실패 6·공구 자동 해제 2, 처치 37·사망 0. **같은 날 기준 회복 2 MP/s + 마나(대) 5개**(`a5_mana_20261026_005843_manual.json`, 교전 약 140초): 마나(대) 5개를 모두 쓰고 체력(중) 3개 사용, 기술 공백 6.5%(7회, 최장 2.7초), 마나 부족 실패 5·공구 자동 해제 3, 처치 36·사망 0. 두 판 모두 약 140초 안에 마나 물약 5개를 다 썼다. 물약이 있으면 2 MP/s에서도 공백이 짧게 유지되지만, 그만큼 소지량이 실제 제한이 된다. 회복량은 추후 조정한다.

**A3·A8 수동 확인 (2026-10-26):** 사용자가 물약 시험과 함께 소환·설치 피드백(A3)과 피격 경직·방패(A8)를 직접 확인했다. 동작 확인이며 수치 균형 승인은 아니다. **이로써 A1~A8 모두 수동 확인을 마쳤다.**

**[기록 주의]** 2026-10-26 수정 전에는 F1·F4·F7~F12로 설정을 바꿀 때 저장된 `*_settings_changed.json`에 **바뀐 뒤의 설정값**이 적혔다(측정한 구간은 바뀌기 전 설정). 2026-10-25의 6개, 23:31~23:32의 3개, 2026-10-26 00:56의 1개가 해당한다. `manual`·`mode_off`·`quit`·`death` 기록은 영향이 없다. 위의 2 MP/s 결정은 플레이 체감에 근거했으므로 바뀌지 않는다.

**A5 수동 시험 기록 (2026-10-25):** 사용자가 [A5 시험 모드](godot_prototype.md#a5-마나-고갈-시험)로 두 차례, 마나 자연 회복 1·2·4 MP/s를 바꿔 가며 볼트 커터 유지 교전을 했다. 기록 10개는 `reports/playtest/`에 있다. 사용자 판단은 다음과 같다. **1 MP/s는 기술을 거의 못 쓰고**, **4 MP/s는 볼트 커터를 유지해도 여유가 있으나 공구를 쓰지 않으면 마나가 계속 차오른다.** 그래서 물약·마나 흡수·마나 회복 옵션에 손이 가도록 **2 MP/s로 약간 모자라게** 가기로 했다([02 §3.1](02_combat.md)). 기록상 산탄(10 MP) 비용 부족 시간은 교전의 약 27~82%로 판마다 편차가 컸다. 공구가 켜진 시간은 공백에서 빠지므로, 기본 공격만 남은 기술 공백 비율은 1~28%로 낮게 잡혔다. 물약·장비 보충은 아직 구현 전이며 그 효과는 C9에서 본다.

**A단계 기본 입력은 합의 완료.** [02 §1.1](02_combat.md)의 즉시 커서 시전 원칙으로 조작을 시험한다. **남은 구현 예외:** 사거리 밖·설치 불가 위치, 유효 대상 부재, 마나 자연 회복·토글 유지 비용·재사용 대기. 세부 예외를 승인된 규칙으로 가장하지 않는다.

## 5. 시험 범위와 보류

**최초 최소 시안 확정 범위:** 전투 필드 1개·기계장치의 마녀 1종·간단한 적·핵심 전투 조작과 대표 스킬만. **허브·프롤로그·메인 퀘스트·NPC·아이템 파밍은 포함하지 않는다.** 이후 B·C 단계로 확대할 경우에만 보스·강적·장비·출동/파밍 루프의 규모를 별도로 결정한다. 확대 시 아이템 구성의 출발점은 §4.1 가안.

**의도적으로 제외:** 시나리오 연출 전체·동사무소·NPC·퀘스트, 모든 스킬/아이템 대량 제작, 유리·재봉의 상세 스킬/플레이어 구현, 전투 수치의 사전 확정, 드롭 경제, 완성 모델링·의상과 시각효과의 대량 제작.

**의사결정 순서:** (1) **우클릭·QWER 즉시 커서 시전 [합의 완료]** 및 입력 예외 검증 → (2) **마나 고갈 체감·회복** → (3) **출혈 스킬 레벨의 구체적 성장 항목·계수** → (4) 전투 수치 조정. 규칙을 바꿔야 할 경우 이 시험판 문서가 아니라 해당 **원본 문서**를 수정한다.
