# 첫 시험판(버티컬 슬라이스) — 제작 준비 명세 초안

> 기획 v0.2 · **[제안]**. 현 단계는 코딩 시작이 아니라 '무엇을 만들면 재미를 검증할 수 있는가'를 정의하는 단계다.

## 1. 시험하려는 핵심 가설

1. **기계장치의 마녀라는 이름 하나에서 화기·구동·자동화 세 전투 방법이 다르게 느껴지는가?**
2. **단순한 기계에서 정교한 기계로 발전하는 성장 체감이 있는가?**
3. **스킬의 대조 특화(A/B)가 진짜 선택을 만들어내는가?**
4. **새 장비를 얻으면 스킬 구성이나 사냥 장소를 바꾸고 싶어지는가?**
5. **6개 액티브 키로 전투와 소환·생존을 모두 조작할 수 있는가?**

## 2. 최소 동작 시험판 → 소형 게임 루프

### A. 조작 시험 (가장 먼저)

- **[제안]** 1종의 캐릭터, 1종 적, 단순 사각형 전장.
- **[합의]** 클릭 이동: 빈 바닥 좌클릭으로 이동, 적 좌클릭으로 해당 슬롯에 등록한 스킬을 시전. **시작할 때 좌클릭에는 마력 소모 없는 기본 공격이 등록**되어 있고, 성장 후 다른 스킬로 교체 가능하다.
- **[제안·최우선 검증]** 구동 공구형 변형을 다른 스킬 슬롯에 등록하고, 변형 후 **기본 공격으로 일정 기간 근접전**을 하다가 나중에 공격 액티브를 습득하는 성장감을 확인한다.
- 기본 공격, 산탄포(광역), 볼트커터 전개(근접·변형), 태엽인형(소환)으로 초기 조작을 검증한다. 시작 좌클릭은 기본 공격으로 고정하고, 추가 기술의 구체적인 키 배치는 시험판에서 정한다.
- 처음에는 데미지 수치보다 **이동, 조준, 근접 판정, 소환 동작, 전환 속도** 확인.
- 구동의 지속 변형 vs 단발 변형은 둘 다 간단히 시험 가능하면 비교. 확정 전 독단 채택하지 않음.

### B. 스킬·생존 시험

- 세 트리에 생존 또는 CC 기술을 1개씩 추가.
- 산탄포의 '확산 넉백' vs '집중 피해' 같은 특화 양자택일을 실제 전투에 적용.
- 적 2~3행동 패턴과 강적 1개를 두고 '혼합 없이' 보스전에 대응 가능한지 확인.

### C. 파밍·육성 시험

- 핵심 매개체 아이템 몇 종류, 매직/희귀 옵션, 고유 효과 1~2개.
- 하나의 아이템 교체가 스킬의 효율이나 보이는 지팡이 외형에 영향을 주는지 확인.
- 짧은 출동 → 드롭 → 빌드 조정 → 다른 방식으로 재출동하는 고리 구현.

## 3. 첫 공개 실험의 범위 가안

| 범주 | 가안 | 조정 가능 여부 |
|---|---|---|
| 플레이어 | 기계장치의 마녀 하나 | 비교적 고정 |
| 스킬 입력 | 클릭 이동 + 좌클릭·우클릭·QWER = 6액티브 슬롯. 첫 좌클릭 스킬은 기본 공격(마력 0), 교체 가능 | 합의 / 변형 시 세부 입력·자동 대체 규칙 미결 |
| 스킬 | 각 트리의 대표 액티브 및 소수 보조기 | 규모 미확정 |
| 적 | 일반 2~3종과 강적 1종 | 임시 |
| 지역 | 허브+전투 지형 1개 | 임시 |
| 보스 | 1종 | 임시 |
| 아이템 | 소수의 베이스/마법/희귀/고유 | 임시 |
| 플레이 루프 | 약 10~15분 한 사이클 | 임시 |

**[미결]** 플랫폼, 게임 엔진, 2D·3D 아트 방향, NPC·UI 방식, 성능 목표, 배포 방법.

## 4. 기능 완료 기준 — [제안]

- **합의된 클릭 이동/좌클릭 시전 규칙**으로 처음 장착한 기본 공격을 사용하고, 성장 후 좌클릭을 다른 스킬로 교체해도 오작동하지 않는다. 자원 고갈 시의 행동은 자동 기본 공격 복귀를 임의로 가정하지 않고 별도 테스트한다.
- 근접 변형 상태에서 다른 스킬 사용 시 조작이 불필요하게 막히지 않는다.
- 공격·제어·방어·소환이 육안으로 구별되고 플레이어에게 피드백이 있다.
- 적의 행동과 공격 범위가 예측 가능해 적중/회피의 책임을 설명할 수 있다.
- 특화 A와 B 모두 어떤 상황에서는 더 나은 선택일 이유가 있다.
- 고유 아이템 없는 빌드도 실제 전투가 되고, 새로운 아이템 착용이 능력/외형에 영향을 준다.
- 자동화 소환체의 길찾기·적 선택이 의도에 맞으며 큰 성능 저하가 없다.
- 첫 파밍 후 다른 사냥 방법으로 다시 실험하고 싶다는 피드백이 나온다.

## 5. 의도적으로 이번에 하지 않을 일

- **[제안에 불과한 이름 예시]** 거울의 마녀·실의 마녀 등 다른 클래스의 확정 스킬트리나 거대한 아이템 데이터베이스. 두 이름은 대화에서 권능의 응용 사례로 든 **가상의 후보**이지 게임 내 등장 또는 플레이어블 클래스가 확정된 것이 아니다.
- 5개 이상의 챕터와 완성된 장편 시나리오.
- 전 영역의 상세 수치·드롭 확률·엔드게임 경제.
- 시각효과/3D 캐릭터/의상 수백 종의 선행 제작.
- 데이터/엔진 세부 사양을 성급하게 확정하는 것.
