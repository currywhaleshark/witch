# 첫 시험판(버티컬 슬라이스) — 제작 준비 명세 초안

> 기획 v0.2 · **[제안]**. 현 단계는 코딩 시작이 아니라 '무엇을 만들면 재미를 검증할 수 있는가'를 정의하는 단계다.

## 1. 시험하려는 핵심 가설

1. **기계장치의 마녀라는 이름 하나에서 화기·구동·자동화 세 전투 방법이 다르게 느껴지는가?**
2. **단순한 기계에서 정교한 기계로 발전하는 성장 체감이 있는가?**
3. **스킬의 대조 특화(A/B)가 진짜 선택을 만들어내는가?**
4. **새 장비를 얻으면 스킬 구성이나 사냥 장소를 바꾸고 싶어지는가?**
5. **6개 액티브 키로 전투와 소환·생존을 모두 조작할 수 있는가?**

## 2. 최소 동작 시험판 → 소형 게임 루프

### A. 조작 시험 (가장 먼저)

- **[제안]** 1종의 캐릭터, 1종 적, 단순 사각형 전장.
- **[합의]** 클릭 이동: 빈 바닥 좌클릭으로 이동, 적 좌클릭으로 해당 슬롯에 등록한 스킬을 시전. **시작할 때 좌클릭에는 마력 소모 없는 기본 공격이 등록**되어 있고, 성장 후 다른 스킬로 교체 가능하다.
- **[합의·현재 방향]** 구동 공구형 변형은 **토글 + 지속 마나 소모**, 다른 공구 변형 스킬 사용 시 기존 공구를 **대체**한다. 변형 후 **기본 공격으로 일정 기간 근접전**을 하다가 나중에 공격 액티브를 습득하는 성장감을 확인한다.
- **[합의]** 적 대상 좌클릭 스킬의 마나가 부족하면 **기본 공격으로 그 사용만 대체**한다(슬롯 내용은 유지). 우클릭·QWER 스킬의 마나 부족은 **발동 실패**한다.
- 기본 공격, 산탄포(광역), 볼트커터 전개(근접·변형), 태엽인형(소환)으로 초기 조작을 검증한다. 시작 좌클릭은 기본 공격으로 고정하고, 추가 기술의 구체적인 키 배치는 시험판에서 정한다. **태엽인형은 초기 시험에서 단순 추적·타격 AI를 먼저 완성한 뒤, 자폭/지속공격 분기 테스트로 확장한다.**
- 처음에는 데미지 수치보다 **이동, 조준, 근접 판정, 소환 동작, 전환 속도** 확인.
- **[합의]** 공구 변형은 **마나 0 시 자동 해제**, **같은 공구 변형 재입력 시 수동 해제**, **다른 공구 변형 성공 시 새 공구로 교체**된다. **다른 계열·처형 스킬을 사용해도 현재 변형은 유지되고 마나 지속 소모 역시 계속된다.** *일부 단발 공격 기술*은 별도로 검토한다.

### B. 스킬·생존 시험

- **[사용자 승인·시험판 기준]** 화기 트리는 현재 [스킬 문서](03_skills.md)의 제시안으로 플레이 테스트를 시작한다. 실제 전투감에 따라 조정하며, 세부 피해량·마나·쿨다운은 **기획 단계에서 고정하지 않는다**.
- **[사용자 제안·현재 방향]** 태엽인형의 **자폭형 vs 지속공격형**을 같은 액티브의 양자택일 특화로 시험한다. 자폭형은 1회성 폭발 후 소멸, 지속공격형은 살아남아 반복 타격하는 행동의 차이를 검증한다.
- 세 트리에 생존 또는 CC 기술을 1개씩 추가.
- **[사용자 제안·현재 방향]** **볼트커터 기본 단일+둔화 / 그라인더 기본 단일+방깎 / 전기톱 기본 작은 범위+출혈**의 타격 판정을 구별한다. 다른 공구로 바꾼 뒤에도 남아있는 디버프가 유지되고, 세 종류가 같은 적에게 **동시에 적용**되는지 시험한다.
- **[사용자 제안·현재 방향]** 공통 **집중 공격/광역 공격** 두 스킬이 활성 공구에 따라 모션·대상 수·디버프를 바꾸는지 확인한다. 각 스킬의 **피해 강화 대 디버프 강화** 선택이 실제로 다른 운용을 만드는지 비교한다.
- **[미결·검증]** 동일 종류 디버프 반복 중첩의 상한·갱신·감쇠와 보스 대상 효과는 별도로 정해야 한다. 공구 3개+공통 공격 2개를 한꺼번에 장착하면 **5슬롯**을 써서 다른 스킬은 1개만 남는다는 선택 비용도 확인한다.
- **[합의·현재 방향]** 낙하 단두대 같은 독립 처형 기술을 기본 지팡이와 어느 공구 변형 상태에서도 사용할 수 있게 한다. **[제안]** 둔화·방어력 감소·출혈이 가진 **기본 효과만으로도** 충분한 처형 연계가 되는지 우선 시험하고, 별도의 추가 시너지 보너스는 필요할 때만 검토한다.
- 산탄포의 '확산 넉백' vs '집중 피해' 같은 특화 양자택일을 실제 전투에 적용.
- 적 2~3행동 패턴과 강적 1개를 두고 '혼합 없이' 보스전에 대응 가능한지 확인.

### C. 파밍·육성 시험

- **[제안·후속 확장]** 자동화의 최상위 **거대 자동인형(가칭)**은 초기 입력·소환 AI와 간단한 육성/파밍 루프가 검증된 뒤 도입한다. **거대한 전투 소환수 한 기체**의 이동·충돌·시야 가림·공존 규칙을 별도로 검증하며, 첫 번째 최소 시험판에서 완성 모델을 만드는 것을 필수로 두지 않는다.

- 핵심 매개체 아이템 몇 종류, 매직/희귀 옵션, 고유 효과 1~2개.
- 하나의 아이템 교체가 스킬의 효율이나 보이는 지팡이 외형에 영향을 주는지 확인.
- 짧은 출동 → 드롭 → 빌드 조정 → 다른 방식으로 재출동하는 고리 구현.

## 3. 첫 공개 실험의 범위 가안

| 범주 | 가안 | 조정 가능 여부 |
|---|---|---|
| 플레이어 | 기계장치의 마녀 하나 | 비교적 고정 |
| 스킬 입력 | 클릭 이동 + 좌클릭·우클릭·QWER = 6슬롯. 첫 좌클릭 기본 공격(마력 0), 교체 가능 | 합의 |
| 자원 부족 | 좌클릭 등록 스킬 마나 부족 → 기본 공격 / 우클릭·QWER → 발동 실패 | 합의, 마나 이외 실패 조건 미결 |
| 구동 변형 | 토글 유지·지속 마나 소모. **같은 변형 재입력 해제 / 다른 변형으로 교체 / 0마나 자동 해제** | 합의, 소모량·전환 애니메이션 미결 |
| 공구 기본 공격 | 볼트커터 단일 둔화 / 그라인더 단일 방깎 / 전기톱 소범위 휘두르기 출혈 | 사용자 제안·현재 방향 |
| 공통 구동 공격 | **집중·광역 2개 액티브 공유**, 각자 **피해 강화 또는 디버프 강화** 선택 | 사용자 제안·현재 방향, 세부 모션/수치 미결 |
| 독립 처형 | 단두대·압착기 등은 기본 지팡이 및 어떤 공구 상태에서도 사용 가능 | 현재 방향 합의, 상태 시너지 미결 |
| 화기 스킬 | 현재 제시한 화기 후보 목록으로 구현·시험 후 수정 | 기준안 승인, 수치 미결 |
| 자동화 초급 | 태엽인형 특화 A 자폭형 / B 지속공격형 | 현재 방향, 발동 조건·수치 미결 |
| 자동화 최상위 | 거대 자동인형(가칭), 기존 자율공방은 보조 후보로 재검토 | 현재 방향, 제작 시점·AI·한도 미결 |
| 스킬 | 각 트리의 대표 액티브 및 소수 보조기 | 규모 미확정 |
| 적 | 일반 2~3종과 강적 1종 | 임시 |
| 지역 | 허브+전투 지형 1개 | 임시 |
| 보스 | 1종 | 임시 |
| 아이템 | 소수의 베이스/마법/희귀/고유 | 임시 |
| 플레이 루프 | 약 10~15분 한 사이클 | 임시 |

**[미결]** 플랫폼, 게임 엔진, 2D·3D 아트 방향, NPC·UI 방식, 성능 목표, 배포 방법.

## 4. 기능 완료 기준 — [제안]

- **합의된 클릭 이동/좌클릭 시전 규칙**으로 처음 장착한 기본 공격을 사용하고, 성장 후 좌클릭을 다른 스킬로 교체해도 오작동하지 않는다. **마나 부족 시 좌클릭만 기본 공격을 대신 쓰고 등록 스킬은 유지**, 우클릭·QWER는 발동하지 않게 검증한다.
- 토글형 공구 변형의 마나 지속 소모와 다른 공구로의 상호 배타적 교체를 검증한다. 마나 0에서 변형 자동 해제도 [합의]대로 검증한다.
- 공구 변형 상태에서 **처형·화기·자동화·생존·CC 스킬**을 사용해도 현재 공구 상태와 유지 마나 소모가 지속된다(그 과정에서 마나 0이 되면 자동 해제).
- **같은 변형 재입력으로 해제**, **다른 공구 변형으로 교체**되는 행동을 각각 검증한다.
- 공구 종류에 관계없이 단두대 같은 독립 처형 스킬이 정상 시전되며, 공구별 별도 상태 연계 보너스는 필수가 아닌 [제안]으로 검증한다.
- 세 디버프가 공구 교체 후에도 유지되고, **서로 다른 디버프의 동시 적용**이 정상 처리되는지 확인한다. 같은 디버프의 반복 중첩 상한은 별도로 설계한다.
- 집중 공격·광역 공격이 모든 공구에서 동작하고, **스킬별 피해 강화/디버프 강화 선택**이 공구 교체 후에도 적용되는지 확인한다.
- 공격·제어·방어·소환이 육안으로 구별되고 플레이어에게 피드백이 있다.
- 적의 행동과 공격 범위가 예측 가능해 적중/회피의 책임을 설명할 수 있다.
- 특화 A와 B 모두 어떤 상황에서는 더 나은 선택일 이유가 있다. 특히 **태엽인형의 자폭형과 지속공격형이 다른 목표·전투 길이에서 각자 쓸모 있는지** 확인한다.
- 고유 아이템 없는 빌드도 실제 전투가 되고, 새로운 아이템 착용이 능력/외형에 영향을 준다.
- 자동화 소환체의 길찾기·적 선택이 의도에 맞으며 큰 성능 저하가 없다.
- 첫 파밍 후 다른 사냥 방법으로 다시 실험하고 싶다는 피드백이 나온다.

## 5. 의도적으로 이번에 하지 않을 일

- **[제안에 불과한 이름 예시]** 거울의 마녀·실의 마녀 등 다른 클래스의 확정 스킬트리나 거대한 아이템 데이터베이스. 두 이름은 대화에서 권능의 응용 사례로 든 **가상의 후보**이지 게임 내 등장 또는 플레이어블 클래스가 확정된 것이 아니다.
- 5개 이상의 챕터와 완성된 장편 시나리오.
- **[합의]** 전 영역의 상세 수치·드롭 확률·엔드게임 경제는 플레이 테스트 전 확정하지 않는다.
- 시각효과/3D 캐릭터/의상 수백 종의 선행 제작.
- 데이터/엔진 세부 사양을 성급하게 확정하는 것.
