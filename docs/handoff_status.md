## 이번에 준비한 코드

- [자산 검사 및 로딩 계약](../tools/scg_assets.py): 원본 MANIFEST 체크섬/크기 비교, 파일 존재, PNG 디코딩/CRC, SHA-256 기록, 지정 캔버스, 알파, 빈/불투명 파츠 검사. 참조 7장의 성격을 완성 일러스트·실험·검사 자료로 구분한다.
- `resolve_layer_plan(spec, appearance)`: 엔진과 무관한 로더 입력. z-order가 정렬된 9개 파츠, 머리/눈 색상 마스크 경로를 반환한다. 세미롱↔트윈테일은 헤어 경로만 바꾸고 공통 파츠를 유지한다. 미지원 설정·중복 슬롯·경로 이탈은 명시적 오류로 처리한다.
- [회귀 검사](../tests/test_scg_assets.py): 누락·손상·1×1 및 전체 투명 대체 이미지·불투명 배경·경로 이탈·미지원 프리셋 등을 검사한다. 임시 테스트 이미지는 저장소 자산으로 사용하지 않는다.

**후속 착수 완료 — 전투 규칙:** [입력·자원·공구 상태 코드](../combat_rules/core.py)와 [JSON 재생 시나리오](../tests/fixtures/combat_rules.json)를 작성했다. 전투 시나리오 13개·38단계 및 전체 테스트 43개(전투 28 + 자산 15)가 통과했다. 실행법·시험 정책·엔진 연결 경계는 [전투 검증 안내](combat_rules_harness.md)에 정리했다. 실제 전투 씬은 여전히 없으며 엔진 선택도 미정이다.

이 인터페이스는 **로딩 계획**이며 합성기·SCG 편집기·3D 연동 구현은 아니다. 기술 검사 통과도 독립 헤어 제작 성공을 뜻하지 않는다. 피부/옷 픽셀 혼입, 가림 복원, sRGB 프로파일, 색상 마스크 정확도 및 경계 품질은 실제 이미지의 별도 검수가 필요하다. 현재 JSON에는 [09 §2.3](09_character_art_pipeline.md)의 의상 `tint_mask.png` 매핑이 없으며, 의상 색 변경은 로딩 계약에 추가하지 않았다.

```powershell
python -m pip install -r tools/requirements.txt
python tools/scg_assets.py --report reports/character_art_audit.json
python -m unittest discover -s tests -v
```

검사 종료 코드: `0`은 원본 MANIFEST가 일치하고 참조 7장과 선택 외형의 필수 파츠가 기술 검사를 통과한 경우, `1`은 누락/잘못된 이미지 또는 원본 체크섬 미검증·불일치가 있는 경우, `2`는 JSON·계약·실행 오류다. `0`도 미선택 헤어/후속 의상 전체 또는 미술 품질의 승인을 의미하지 않는다. 전체 스타일은 보고서의 개별 항목을 확인한다.

**이번 실행:** 회귀 검사 15개 통과. 원본 20개 파일의 체크섬 일치, 참조 PNG 7장 기술 검사 통과. 생산용 파츠 16개가 없으므로 실제 자산 검사는 종료 코드 `1`을 반환한다. 누락을 성공으로 우회하지 않았다.

## P0 작업 순서 — 구현 제안

우선순위는 [06 §0·단계 A](06_vertical_slice.md)다. 현재는 사용자 선택에 따라 엔진 독립 준비 단계에 머문다. 이후 엔진을 선택하면 다음 단위로 구현한다. 아래는 작업 분할이며 새 게임 규칙의 확정이 아니다.

1. 임시 도형 기반 단일 3D 필드·쿼터뷰 카메라·플레이어·지면/적 커서 판정. A1부터 직접 검증한다. 완성 캐릭터 아트가 없어도 시작할 수 있다.
2. 6슬롯 입력 경로와 시전 요청을 분리하고 A1/A2를 검증한다. 입력 정책의 원본은 [02 §1](02_combat.md).
3. 기본 공격·적의 추격/공격·HP/MP·피격/사망 피드백으로 한 필드에서 전투 가능 상태를 만든다.
4. [03](03_skills.md)의 대표 화기·공구·이동형 소환·설치 예시를 최소량으로 연결하고 A3~A5를 검증한다.
5. 수치와 미결 입력 예외는 별도 시험 설정/기록에 임시값임을 표시한다. 시험 결과에 따라 담당 원본 문서에서 결정한다.

**확정 범위:** 최초 전투 필드와 [02](02_combat.md)의 입력·마나 규칙. **제안/현재 방향:** 개별 기술 후보와 일부 소환 동작, 아트 레이어의 초안 계약. **미결:** 엔진, 사거리/유효 표적 실패 처리, 회복·유지비·재사용 수치, [07](07_attributes.md)의 성장·피해 계수. 이를 임의로 승인 상태로 바꾸지 않았다. 시나리오·허브·SCG/커스터마이징 UI는 현재 작업 목록에 넣지 않는다.

## 다음 작업과 남은 자산

1. 입력/시전 요청·공구 상태·자원 소비 인터페이스와 자동 검증은 준비했다. 엔진 선택 후 도형 필드의 피킹·길찾기·공격·적 대응·HP/MP에 연결하고 [06](06_vertical_slice.md)의 실제 플레이 검증을 진행한다.
2. 아트 A1은 공통 헤어리스 바디 복원과 독립 세미롱/트윈테일 파츠 제작이 필요하다. 현재 참조만으로 A2 합성 성공을 선언하지 않는다.
3. 3D는 전신 기준도·모델·리그가 제공된 다음 검사한다. 2D 의상 색 변경 계약은 실제 의상 파츠와 마스크 매핑을 추가한 후 확장한다.
4. 새 자산이 도착하면 검증 보고서를 다시 생성한다. 원본을 수정하는 대신 파생 제작물은 별도 생산용 경로에 둔다.
