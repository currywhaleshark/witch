## 실행

Godot 4.6에서 [game/project.godot](../game/project.godot)을 열고 F6가 아닌 **F5(프로젝트 실행)**를 누른다. Windows에서는 저장소 루트에서 다음 명령으로도 실행할 수 있다.

```powershell
powershell -ExecutionPolicy Bypass -File tools/run_godot.ps1
# 자동 탐색되지 않는 경우
powershell -ExecutionPolicy Bypass -File tools/run_godot.ps1 -GodotPath 'C:\path\Godot_console.exe'
```

실행기는 PATH 또는 사용자 Downloads의 Godot 4 실행 파일을 찾고 자산 임포트 후 실행한다. 엔진이나 추가 패키지를 다운로드하지 않는다. 플레이 가능한 소스 프로젝트이며 독립 실행 파일 배포본은 아직 만들지 않았다.

### 시작 로딩 화면과 미리 불러오기 (2026-11-01)

사용자가 변신·소환 때의 멈칫함을 보고 시작 시 미리 불러오기와 임시 로딩 화면을 요청했다. 게임 시작 장면은 [boot.tscn](../game/boot.tscn)이다. [boot.gd](../game/scripts/boot.gd)가 첫 프레임부터 [임시 로딩 화면](../game/scripts/loading_screen.gd)을 띄우고, 전투 필드와 캐릭터 파일을 스레드로 불러온 뒤 arena로 넘긴다. arena는 같은 화면 뒤에서 [asset_warmup.gd](../game/scripts/asset_warmup.gd)를 실행한다.

1. 처음 쓸 때 불러오던 변신 의상·소환체·적·보스·지팡이 모델과 효과 셰이더를 스레드로 불러와 참조를 유지한다.
2. 변신 의상의 텍스처 내용 키를 미리 계산한다. 원인은 [modular_character_runtime.gd](../game/scripts/modular_character_runtime.gd)가 파츠를 붙일 때마다 모든 텍스처 픽셀을 GPU에서 읽어 SHA-256으로 비교하던 것이다. 변신 의상에서는 공개 시작과 교체 때 각 약 1.4초가 걸렸다. 이제 텍스처 객체별로 한 번만 계산해 둔다.
3. 소환체·조립 파츠·산탄·스프링·방패·지팡이·변신 의상(공개 셰이더 포함)과 효과 셰이더를 화면 뒤에 몇 프레임 그려, Compatibility 렌더러가 셰이더를 지금 컴파일하게 한다.

로딩 중에는 전투 시계·입력·필드 진입 변신이 멈춰 있고, 끝나면 변신이 시작된다. `preload_mode`는 필드 진입과 같은 Auto/Always/Disabled 규칙이다. Auto는 일반 실행에서만 켜지고, main.tscn을 직접 불러오는 검사·리뷰 스크립트에서는 꺼진다. 프레임 시간은 [hitch_probe.gd](../game/tests/hitch_probe.gd)로 실제 GPU 창에서 쟀다([측정 결과](../reports/asset_warmup_v1/)). 셰이더 캐시를 비운 첫 실행 / 캐시가 있는 실행 기준으로 가장 긴 프레임은 다음과 같다.

| 구간 | 이전 | 이후 |
|---|---|---|
| 필드 진입 변신 | 2232 / 1501ms | 39 / 26ms |
| 첫 태엽인형 | 251 / 143ms | 78 / 29ms |
| 첫 포탑 | 147 / 168ms | 78 / 59ms |
| 첫 공구 변형 | 586 / 17ms | 66 / 15ms |
| 첫 산탄 | 35 / 40ms | 45 / 46ms |

포탑(약 60~80ms)과 산탄(약 45ms)은 아직 한 프레임 정도 끊긴다. 로딩 자체는 약 3~4초 걸린다. 수치는 이 PC(RTX 2060) 한 대의 측정이며 성능 승인이 아니다. 로딩 화면은 디자인이 정해지지 않은 임시 화면이다.

**바닥 아이템 드롭 끊김 (2026-11-02):** 사용자가 드롭 때마다 프레임이 떨어진다고 알렸다. 실제 GPU 창에서 39종을 한 번씩 떨어뜨리고 마우스를 올려 재 보니, 드롭 직후 몇 프레임이 최대 276ms, 강조 때 최대 166ms까지 늘었다(평소 12ms 이하). 주원인은 이름표 배치였다. [ground_loot.gd](../game/scripts/ground_loot.gd)가 이름표마다 화면 전체 격자 약 1,700칸을 후보로 만들어 정렬했고, 떨어지는 동안과 카메라가 움직이는 동안 이를 매 프레임 다시 계산했다. 이제 거리순 격자 순서를 이름표 크기별로 한 번만 정렬해 두고, 가까운 칸부터 보다가 빈칸을 찾으면 멈춘다. 후보 순서는 같다(같은 거리는 열·행 순서로 고정). 또 asset_warmup이 바닥 아이템 모델 39종을 로딩 중에 불러오고, 놓인 모습과 강조된 모습, 선택 고리를 한 번씩 그린다. 같은 측정에서 가장 긴 프레임은 드롭 276ms→36~42ms, 강조 166ms→24~31ms로 줄었고, 이름표 39개 전체 배치는 4.4ms다. 남은 33ms 안팎 프레임은 매번 다른 아이템에서 한 번씩 생긴다.

## 구현 경계와 시험 선택

입력·자원 원본은 [02](02_combat.md), 기술 원본은 [03](03_skills.md), 피해 규칙 원본은 [07](07_attributes.md), HUD 원본은 [10](10_ui.md)다. 아래 내용은 이 시안의 임시 구현 선택이며 기획 승인으로 바꾸지 않는다.

- [trial.json](../game/data/trial.json)은 `test_values_not_approved_balance`로 비용·재사용·피해·적 체력·유지비·회복·소환 수명 등을 보관한다. 산탄은 부채꼴 즉시 공간 판정이며 탄도 시뮬레이션은 아니다.
- 비용/쿨다운/공구의 단일 시전 검사는 Python 참조 구현과 같은 정책이다. Godot 이동 계층이 사거리 부족 결과를 받아 대상을 기억하고 접근한 뒤 다시 검사한다. 좌클릭 적 공격 성공은 이전 클릭 이동을 대체하고, 우클릭·QWER 시전은 이동 명령을 지우지 않는다(아래 이동 중 시전). Shift 바닥 조준은 방향을 선택하며 실제 피해 사거리를 제한한다. 설치는 필드 경계·거리·캐릭터/소환체와의 겹침을 검사한다.
- 기술마다 `targeting: direction` 표시가 있으면 공간 판정에서 사거리 부족을 내지 않아 접근 후 시전을 건너뛴다. 현재 산탄만 방향 지정형이며, 기본 공격·포탑·표적 중계·태엽인형은 기존대로 접근한다. 이 표시는 Godot 시험 설정이며 Python 규칙 계약은 바뀌지 않는다.
- 접근 중에는 적의 현재 위치를 추적하고 지면 좌표는 고정한다. 시작 시 자원은 소비하지 않으며 실제 시전 때의 자원으로 기술/좌클릭 대체 여부와 사거리를 다시 판단한다. 현재 직선 이동이 1.5초간 진행하지 못하면 취소한다. 이 시간과 취소·대기 세부 정책은 [02 §1.1](02_combat.md)의 구현 시험값이다.
- 물리 프레임마다 쿨다운/유지비 → 0마나 해제 → 외부 자연회복(시험값 2 MP/s) 순으로 처리한다. 회복으로 공구가 자동 재활성화되지는 않는다. GDScript는 부동소수점과 1e-8 소진 허용오차를 사용하며 소수 유지비 고갈도 검사했다.
- 기본 태엽인형은 **소환 시점부터** 시험 수명이 진행되고 마지막에 범위 자폭한다. 포탑은 위치를 유지하며 근처 적에게 사격한다. 이동형은 화면 밖이면 플레이어에게 돌아온다. 소환체 몸막·복잡한 장애물 길찾기는 아직 없다(소환체 체력과 피격은 아래 항목).
- **스프링 돌진 시험 구현 (2026-10-30, [03 구동 II](03_skills.md)):** C1 첫 플레이에서 구동에 접근·탈출 수단이 필요하다는 의견으로 넣었다. 커서 방향으로 짧게 튀어 나가는 액티브(마나 8, 쿨타임 3초, 준비 0.12초, 돌진 0.2초)로, 커서 지점까지 최소 1.5m·최대 5m를 간다. 적을 가리키면 1.2m 앞에서 멈춘다. 걸을 수 있는 바닥 밖으로는 나가지 않고 벽에 막히면 그 자리에서 끝난다. 돌진 중에는 피해는 받지만 경직되지 않는다. 산탄처럼 사거리 밖이어도 다가가지 않는다. 기본 슬롯에는 없고 S 창에서 등록한다. 모두 시험값이다.
  - **착지 노드(2026-11-05, 1점, 택1):** S 창 구동 탭 아래 노드 줄에서 고른다. 스킬 레벨은 여전히 없다. **접근 착지**는 내려선 자리 반경 1.8m 안의 시야가 트인 적을 1.2초 기절시킨다(구동이 붙어서 자르기 좋게). **후퇴 착지**는 반경 2.4m 안의 적을 마녀에게서 2.2m 밀어낸다(화기·자동화가 거리를 벌리기 좋게. 무거운 적은 절반). 둘 다 피해와 명중 굴림이 없고 보스에게는 듣지 않는다(돌진 중인 철문 아귀도 밀리지 않음). 기본 판은 착지 효과가 없다. 반동 도약은 같은 도약 이동을 쓰지만 착지 효과가 없다. [스프링 돌진 노드 검사](../game/tests/spring_dash_nodes.gd).
- **마나 흐름 기록·물약 공급 시험 구현 (2026-11-01, C9·C10, [02 §3.1](02_combat.md), [04 §8.2](04_items.md)):** 수치는 `items.json`의 시험값이다.
  - **마나 흐름(C9):** A5 기록 `metrics.mana_flow`에 기술 시전으로 쓴 마나(`casts`)·공구 유지비(`upkeep`)·자연 회복(`regen`, 장비 회복 옵션 포함)·마나/회복 물약(`potions`)이 쌓인다. 동력 부품·유지비 옵션·마나 물약이 마나 공백을 어떻게 메웠는지 이 네 값으로 비교한다.
  - **공구 공격 기록 분리 (2026-11-05):** 집중·광역 공격의 피해는 `metrics.by_source`에서 `focus_attack:<공구>`·`area_attack:<공구>` 줄로 따로 쌓이고, 공구 이름만 있는 줄(`grinder` 등)은 그 공구의 기본 공격이다(피해 계산은 여전히 공구를 출처로 본다). `metrics.channels`에는 누르고 있는 공격(`focus_attack:<공구>`, `gatling`)마다 횟수·총 유지 시간·최장·평균·그동안 쓴 마나가, `metrics.upkeep_by`에는 유지비가 공구·총기·집중·기관포별로 나뉘어 남는다(합은 `mana_flow.upkeep`). 집중 공격의 유지 시간은 진입 동작(0.3초) 뒤부터 잰다. 전기톱 출혈은 여전히 `bleed` 한 줄이다. [기록 검사](../game/tests/tool_attack_log.gd).
  - **물약 보관함(C10):** 처치 시 물약이 바닥에 떨어지며 클릭해 주우면 보관함으로 들어간다([04 §9](04_items.md); 일반 8%·강화 15%·정예 35%·보스 확정, 소형 위주, 완전 회복 3종은 드롭 전용). I → 「물약」에서 각인전으로 산다(소 10·중 25·대 50, 회복 물약 20/40/70, 이동 속도 30). 보관함은 재시작해도 유지되고, 재시작하면 퀵슬롯은 지금처럼 기본 구성으로 다시 채워진다.
  - **퀵슬롯 구성:** 「물약」의 15칸 가방에서 묶음을 클릭해 집고 아래 1~4번 슬롯에 놓는다. 자리 교환·회수·선택 취소는 [10 §4](10_ui.md#4-하단-바-메뉴와-단축키--합의)를 따른다. 04의 합의대로 퀵슬롯이 비어도 보관함에서 저절로 채워지지 않는다. Shift+1~4 시험 도구는 그대로다.
- **적 레벨 시험 구현 (2026-11-01, [05 §2](05_content.md)):** C7~C10 플레이에서 모든 빌드가 굉장히 강해졌다는 소감이 나왔다. 빌드는 시험 레벨 30인데 적에는 레벨이 없었으므로, 사용자 요청으로 적 레벨을 넣었다. 적 체력은 레벨당 +9%(Lv30 ×3.61), 공격 피해는 레벨당 +6%(Lv30 ×2.74; 2026-11-02에 +5%·×2.45에서 상향)로 등급 배율에 곱한다. 기본은 시험 레벨을 따라간다. 캐릭터창(C)의 「적 레벨」 −/+(Ctrl ×5, Shift ×10)로 따로 정하면 그 값에 고정되고, 「적 레벨을 시험 레벨에 맞춤」으로 되돌린다. 바꾸는 즉시 살아 있는 적도 체력 비율을 유지한 채 바뀐다. 출혈 총량·보스 단계·마녀 경직 기준은 최대 체력 비율이라 함께 따라간다. 회피·이동 속도·처치 보상·드롭 아이템 레벨은 그대로다. 적 이름에 Lv가 붙고 A5 기록 빌드에 적 레벨이 남는다. 수치는 `trial.json` `build`의 `enemy_hp_per_level`·`enemy_damage_per_level` 시험값이다.
- **임시 UI 정리 (2026-11-02, [10 §4](10_ui.md)):** 사용자 요청으로 인벤토리와 스킬트리창을 옛 액션 RPG식으로 바꿨다. 배치·크기·그림은 모두 임시다.
  - **격자 가방:** 장비 칸 7개를 인형 모양으로 놓고 그 아래 10×6칸 가방을 둔다. 아이템은 부위별 크기만큼 칸을 차지한다(의상 2×3, 매개체·머리장식·장갑·신발 2×2, 브로치·반지 1×1, `items.json`의 `slot_sizes`; 매개체는 2026-11-02 사용자 요청으로 2×3에서 2×2로 줄임). 주운 아이템은 왼쪽 위부터 세로로 빈 자리를 찾는다. 인벤토리가 열려 있으면 바닥 장비를 주울 때 가방에 바로 넣지 않고 커서에 든다(정리하기 쉽게; 화폐·이름 파편·물약은 그대로 들어감). 아이템 그림은 칸 가운데에 비율을 유지한 채 칸을 거의 채우고, 소켓은 그림 위 아래쪽에 겹쳐 그린다. 그림 영역은 알파 24/255를 넘는 보이는 픽셀로 잡는다(256px로 줄일 때 생기는 거의 투명한 가장자리까지 잡으면 코트 등이 칸 가운데보다 약 4px 오른쪽에 그려졌음).
  - **조작:** 클릭하면 아이템이 커서에 들리고, 다시 클릭하면 놓인다. 놓는 자리 밑에 아이템이 하나 있으면 서로 바뀌고 둘 이상이면 놓이지 않는다. 들고 장비 칸을 누르면 착용(입던 것이 커서로), 장비를 누르면 커서로 든다. 우클릭은 바로 착용·벗기. 모루 칸에 놓으면 분해, 들고 창 밖을 클릭하면 발밑 바닥으로 버린다(그 클릭으로 공격은 나가지 않는다). 바닥 아이템은 걸어 지나가도 줍지 않고, 클릭해야 걸어가 줍는다(2026-11-02 사용자 요청, 줍는 반경 1.1m). 바닥 아이템과 라벨의 겹침 방지·마우스오버 강조는 [10 §4](10_ui.md)를 따른다. 다른 이동·스킬 입력이 들어오면 줍기를 그만둔다. 창 안의 클릭은 처리하기 전에 먼저 받아 둔다(2026-11-02 수정: 클릭이 창을 다시 그리는 사이 필드로 새어, 왼클릭으로 집은 아이템이 곧바로 버려지고 우클릭 착용 때 우클릭 스킬이 나가던 문제). 창을 닫거나 재시작하면 든 아이템은 가방으로 돌아가고, 자리가 없으면 바닥에 놓인다.
  - **임시 장비 그림:** 베이스마다 단순한 도형(반지·브로치·리본·머리핀·덧옷·망토·장갑·신발·유리구슬·결정·설계도·톱니)을 코드로 그리고 테두리는 등급 색이다. 소켓은 아래쪽 구멍으로, 끼운 조각은 음절(벨·록·샤)로 보인다. 마우스를 올리면 바로 설명이 뜨고 이름은 등급 색, 가방 아이템은 지금 착용한 것과 비교한다.

[청취 페이지](../reports/combat_sfx_v1/review.html)와 생성 기록을 참조한다. [효과음 검사](../game/tests/combat_sfx.gd)는 모든 효과음 파일 로드·재생, 타격 변형 연속 중복 없음, 동시 재생 상한, 긴 꼬리 페이드, 음소거, 파일 누락 시 기존 소리 대체를 확인한다([보고서](../reports/combat_sfx_v1/godot_sfx_report.json)). 실제 귀로 듣는 음량 균형은 검사하지 않는다.

  - **스프링 돌격·방패 전개 교체 (2026-11-01):** 사용자가 ElevenLabs에서 받아 온 두 파일로 `spring_dash.wav`(묵직한 산업 기계 소리)와 `shield_raise.wav`(짧은 중세 갑옷 소리)를 바꿨다. 스프링 파일은 앞 0.22초가 무음이라 건너뛰어 발판 작동 순간에 소리가 나게 했다. 음량(-19dB, -25dB)은 이전 파일의 가장 큰 구간에 맞춘 시험값이다. 처음 생성본은 `reports/combat_sfx_v1/rejected/`에 남겼다.
  - **공구 구동음 (2026-11-01):** 그라인더·전기톱을 꺼내 둔 동안 각자의 구동음(`grinder_idle.wav`·`chainsaw_idle.wav`, ElevenLabs에서 끊김 없는 반복용으로 생성한 4초 파일, 가져오기 설정에서 반복 재생)을 계속 깐다. 공격·시전 동작 중에는 음량 +4dB·피치 +8%로 회전이 올라가고, 공구를 넣거나 바꾸면 0.25초에 걸쳐 사라지거나 교차한다. 일시정지·사망·필드 정리·변신 중에는 멈추고 M은 즉시 끈다. 음량(그라인더 -26dB, 전기톱 -27dB)은 타격음 아래에 깔리도록 맞춘 뒤 사용자 요청으로 두 번에 걸쳐 모두 7dB 낮춘 시험값이다.

## A5 마나 고갈 시험

[06 A5](06_vertical_slice.md)의 "아무 기술도 못 쓰는 구간"을 직접 플레이하며 재기 위한 시험 모드다. 측정 기능이며 마나 규칙이나 수치를 바꾸지 않는다.

1. 게임을 실행하고 **F5**로 연속 교전을 켠다. 적이 쓰러지면 2.5초 뒤 마녀에게서 먼 필드 가장자리에서 같은 종류가 다시 나와 적 6마리를 유지한다. 필드 정리 완료 화면은 나오지 않는다.
2. 평소처럼 **Q 볼트 커터를 켠 채** 산탄·태엽인형·포탑을 섞어 싸운다. 회복량을 비교하려면 **F7**로 1·2·4 MP/s를 바꾸고 각각 2~3분씩 싸운다. 기본값 2는 첫 A5 시험 뒤 사용자가 고른 약간 모자란 기준이다([02 §3.1](02_combat.md)).
3. 왼쪽 패널에서 실시간 값을 본다. **기술 공백**은 공구가 꺼져 있고 마나를 쓰는 등록 기술을 하나도 쓸 수 없는, 즉 기본 공격만 남은 교전 시간이다. 총 시간·교전 대비 비율·횟수·최장 시간, 지금 공백인지, 마나 부족 실패·좌클릭 대체 공격·공구 자동 해제 횟수를 표시한다. 공구는 비용 0이라 마나가 조금만 있어도 켤 수 있지만 곧 다시 해제되므로 공백 판정에서 제외했다.
4. 기록은 `reports/playtest/a5_mana_<시각>_<이유>.json`에 저장된다. **F6**, 사망, 일시정지·사망 후 Enter 재시작, F5 종료, 창 닫기 때 저장한다. F7·F4·F1(및 F8~F12)로 설정을 바꾸면 **바꾸기 전 설정으로** 그때까지의 기록을 저장하고 새로 잰다. 한 기록에 두 설정이 섞이지 않게 하려는 것이다. 2026-10-26 이전의 `settings_changed` 기록에는 바뀐 뒤 값이 적혀 있다([06 기록 주의](06_vertical_slice.md)). 기록에는 회복량·스킬 비용·재사용 대기·유지비·등록 슬롯, 스킬별 비용 부족 시간, 시전 횟수가 들어간다. F2/F3 사용 횟수는 `debug_mana_edits`로 남는다. F8도 설정 변경으로 새로 재며, 기록에 시전 속도 점수와 기술별 실제 시전 시간이 들어간다.
5. 숫자와 함께 **답답했던 순간과 그때 하려던 행동**을 메모해 둔다. 기록 파일은 체감을 대신하지 않는다.

HP 회복과 물약이 없어서 오래 싸우면 쓰러질 수 있다. 사망하면 그 시점까지의 기록이 저장된다. 시험 설정의 원본은 [trial.json](../game/data/trial.json)의 `mana_regen_steps`, `a5_respawn_seconds`다.

## 자동 검증과 남은 확인

```powershell
python -m unittest discover -s tests -v
powershell -ExecutionPolicy Bypass -File tools/run_godot.ps1 -Verify
powershell -ExecutionPolicy Bypass -File tools/run_godot.ps1 -RenderCheck
```

**전체 회귀 실행기 (2026-11-06):** `-Verify`는 16개만 돌리고 첫 실패에서 멈춘다. 리팩터링 등 넓은 변경 전후에는 [run_regression.ps1](../tools/run_regression.ps1)로 전체를 끝까지 돌리고 [기준선](../reports/regression/baseline.json)과 비교한다.

```powershell
powershell -ExecutionPolicy Bypass -File tools/run_regression.ps1 -Jobs 3 -Baseline reports/regression/baseline.json
powershell -ExecutionPolicy Bypass -File tools/run_regression.ps1 -Only items,boss -NoImport
powershell -ExecutionPolicy Bypass -File tools/run_regression.ps1 -Jobs 3 -SaveBaseline
```

- 대상 목록은 [regression_suite.json](../game/tests/regression_suite.json)이다. `game/tests/*.gd`는 모두 `headless`·`gpu`·`excluded`(사유 기록, `review_*` 등 캡처·자산 준비·측정 스크립트) 중 하나에 있어야 하며, 빠진 새 테스트는 실행기가 경고한다. 새 회귀 테스트를 만들면 여기에 추가한다.
- 테스트마다 `--output`의 뜻이 다르다(파일/폴더). `output_file`·`output_dir`에 적힌 테스트는 실행 폴더 안의 경로를 받는다. 대부분은 이 인자 없이 실행하면 저장 단계에서 SCRIPT ERROR로 멈춘다.
- 결과는 `reports/regression/runs/<시각>/`(git 제외)의 테스트별 로그와 `summary.json`에 남는다. 테스트가 다시 쓴 추적 중인 `reports/` 파일은 실행 뒤 git에서 복원한다(`-KeepReports`로 유지). 그 밖에 바뀐 파일·새 파일은 목록만 남긴다. 실행 전부터 수정돼 있던 보고서 파일은 복원 대상이 아니다.
- 기본으로 먼저 임포트를 실행한다(새 에셋의 임포트 캐시가 없으면 해당 테스트가 실패한다). 임포트는 Godot가 `.import` 파일을 다시 쓸 수 있다. 이미 최신이면 `-NoImport`로 생략한다.
- SCRIPT ERROR 뒤 `quit()`에 도달하지 못한 테스트는 로그가 `-StallSec`(기본 45초) 동안 멈추면 끊고 `script_error`로 기록한다. 전체 제한은 `-TimeoutSec`(기본 600초).
- `-Baseline`을 주면 기준선에서 통과하던 테스트가 실패할 때만 종료 코드 1이다. 병렬(`-Jobs`)은 같은 `user://` 폴더를 쓰므로, 병렬에서만 실패하면 `-Only`로 단독 재실행해 확인한다.
- 기준선의 알려진 실패: `transformation_v25`는 v26 입장 클립 교체 뒤 v25 Blender 자세(오차 약 0.39m)와 효과음 연결 기대가 맞지 않는다. 같은 범위를 v26·v27 테스트가 통과한다.
