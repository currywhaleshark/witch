# Godot 전투 필드 실행 안내

2026-10-25 · Godot 권고 뒤 사용자의 “푸시하고 시작해보자” 요청을 받아 **Godot 4.6 + GDScript**로 첫 도형 전투 시안을 구현했다. 설치된 **4.6.2 stable / Compatibility / Windows**에서 검사했다. 기존 인계·Python 작업은 `9b711cd`까지 `origin/main`에 푸시 완료했다. 이번 Godot 구현의 작업 상태는 Git 상태를 별도로 확인한다.

## 실행

Godot 4.6에서 [game/project.godot](../game/project.godot)을 열고 F6가 아닌 **F5(프로젝트 실행)**를 누른다. Windows에서는 저장소 루트에서 다음 명령으로도 실행할 수 있다.

```powershell
powershell -ExecutionPolicy Bypass -File tools/run_godot.ps1
# 자동 탐색되지 않는 경우
powershell -ExecutionPolicy Bypass -File tools/run_godot.ps1 -GodotPath 'C:\path\Godot_console.exe'
```

실행기는 PATH 또는 사용자 Downloads의 Godot 4 실행 파일을 찾고 자산 임포트 후 실행한다. 엔진이나 추가 패키지를 다운로드하지 않는다. 플레이 가능한 소스 프로젝트이며 독립 실행 파일 배포본은 아직 만들지 않았다.

## 첫 플레이

| 입력 | 시안에서 확인할 동작 |
|---|---|
| 좌클릭 | 빈 땅 이동 / 적에게 접근해 사거리 안에서 공격 |
| 좌클릭 유지 | 바닥에서 누르면 커서를 따라 계속 이동 / 적 위에서 누르면 그 적을 고정해 반복 공격 |
| Shift + 좌클릭 | 이동을 멈추고 제자리 공격 |
| 우클릭 | 커서 방향 산탄 공격. 먼 적·지면을 가리켜도 다가가지 않고 제자리에서 즉시 발사. 유지하면 재사용 대기마다 반복 |
| Q | 볼트 커터 토글, 기본 공격 강화·둔화, 같은 키로 해제 |
| W | 플레이어 옆 태엽인형 생성, 커서 적을 초기 표적으로 사용 |
| E | 커서 지면에 포탑 설치 |
| R | 해당 적을 공격할 수 있는 소환체에 표적 중계 |
| Esc / Enter | 일시정지·복귀 / 정지·사망·필드 완료 화면에서 재시작 |
| M / H | 효과음 끄기·켜기 / 조작 도움말 |
| F1 / F2 / F3 / F4 | **시험 도구:** 좌클릭 기본/산탄 교체 / 마나 소진 / 마나 회복 / 공격 속도 점수 0·20·40 순환. 일시정지를 해제한 상태에서 사용 |

[02 §1의 누르고 있기](02_combat.md)를 따른다. 적 위에서 누른 입력은 커서를 옮겨도 그 적을 계속 공격하고, 떼거나 적이 쓰러지면 멈춘다. 공구 토글·소환·설치 키는 누르고 있어도 한 번만 시전한다. 먼 적이나 지면을 지정하면 [02의 사거리 확보 후 시전](02_combat.md)을 수행한다. Shift+좌클릭은 제자리에서 시전한다. 접근을 취소하려면 다른 땅을 클릭하거나 다른 기술을 사용한다. 1~4 물약 슬롯은 비어 있으며 물약 시스템을 구현한 것으로 표시하지 않는다. 캐릭터/스킬/장비/퀘스트 메뉴는 현재 숨겼다.

## 구현 경계와 시험 선택

입력·자원 원본은 [02](02_combat.md), 기술 원본은 [03](03_skills.md), 피해 규칙 원본은 [07](07_attributes.md), HUD 원본은 [10](10_ui.md)다. 아래 내용은 이 시안의 임시 구현 선택이며 기획 승인으로 바꾸지 않는다.

- [trial.json](../game/data/trial.json)은 `test_values_not_approved_balance`로 비용·재사용·피해·적 체력·유지비·회복·소환 수명 등을 보관한다. 산탄은 부채꼴 즉시 공간 판정이며 탄도 시뮬레이션은 아니다.
- 비용/쿨다운/공구의 단일 시전 검사는 Python 참조 구현과 같은 정책이다. Godot 이동 계층이 사거리 부족 결과를 받아 대상을 기억하고 접근한 뒤 다시 검사한다. 성공한 시전은 이전 클릭 이동을 중단한다. Shift 바닥 조준은 방향을 선택하며 실제 피해 사거리를 제한한다. 설치는 필드 경계·거리·캐릭터/소환체와의 겹침을 검사한다.
- 기술마다 `targeting: direction` 표시가 있으면 공간 판정에서 사거리 부족을 내지 않아 접근 후 시전을 건너뛴다. 현재 산탄만 방향 지정형이며, 기본 공격·포탑·표적 중계·태엽인형은 기존대로 접근한다. 이 표시는 Godot 시험 설정이며 Python 규칙 계약은 바뀌지 않는다.
- 접근 중에는 적의 현재 위치를 추적하고 지면 좌표는 고정한다. 시작 시 자원은 소비하지 않으며 실제 시전 때의 자원으로 기술/좌클릭 대체 여부와 사거리를 다시 판단한다. 현재 직선 이동이 1.5초간 진행하지 못하면 취소한다. 이 시간과 취소·대기 세부 정책은 [02 §1.1](02_combat.md)의 구현 시험값이다.
- 물리 프레임마다 쿨다운/유지비 → 0마나 해제 → 외부 자연회복(시험값 2 MP/s) 순으로 처리한다. 회복으로 공구가 자동 재활성화되지는 않는다. GDScript는 부동소수점과 1e-8 소진 허용오차를 사용하며 소수 유지비 고갈도 검사했다.
- 기본 태엽인형은 **소환 시점부터** 시험 수명이 진행되고 마지막에 범위 자폭한다. 포탑은 위치를 유지하며 근처 적에게 사격한다. 이동형은 화면 밖이면 플레이어에게 돌아온다. 소환체의 체력·몸막·피격·복잡한 장애물 길찾기는 아직 없다.
- 기본 공격은 재사용 대기 없이 **공격 동작 시간**으로 반복 간격이 정해진다. [04 §4.1](04_items.md)의 제안 곡선 `최소 + (기본 − 최소) / (1 + k × 공속 점수)`에 시험값(기본 0.6초, 볼트 커터 0.95초, 최소 0.25초, k 0.04, 시작 점수 0)을 넣었다. 동작 중에는 이동하지 않고, 그 사이 마지막 입력은 동작이 끝난 뒤 실행한다. 산탄 등 다른 기술은 시전 동작 시간 없이 재사용 대기만 있다.
- **카메라 각도는 고정**이다(사용자 요청). 직교 투영에 좌우 45°·내려다보는 각 30°를 써서 바닥 격자가 2:1 마름모로 보이는 2D 쿼터뷰 형태다. 마녀를 따라갈 때 평행 이동만 하고 지연·회전 없이 마녀를 화면 중앙보다 약간 아래에 둔다. 확대 배율(직교 크기 20)은 시험값이다.
- 적 선택은 이동 충돌 캡슐과 별도인 **모델 전체 크기의 선택 원기둥**(Area3D)으로 판정한다. 적이 어느 방향을 보더라도 머리·팔·발을 눌러 선택할 수 있다.
- 플레이어와 적은 충돌체가 있고 바깥 벽을 통과하지 않는다. 내부 장애물이 없는 평면 필드라 클릭 이동은 직선 이동이다. 적은 일반/무거운 도형 2종이며 추격·공격 예고·피격·처치가 가능하다.
- 피해는 **고정 시험값**이다. [07](07_attributes.md)의 성장 스탯·명중 굴림·치명·출혈 전체를 구현한 상태가 아니다. 표적 중계기의 스킬 레벨 보너스·공구 3종 전체·스킬 성장/특화도 후속 범위다.
- 적 머리 위 HP/둔화, 상단 공구 상태·고갈 경고, 플레이어 머리 위 실패 문구, 하단 6슬롯의 쿨다운/마나 부족 및 세로 HP/MP 게이지를 표시한다. 피해 숫자와 음성 안내는 없다.
- 도형 캐릭터와 필드는 [shapes.gd](../game/scripts/shapes.gd)의 임시 메시다. 제공된 원화를 3D 모델로 변환한 것이 아니며 독립 PNG 파츠·리그·애니메이션은 여전히 미제작이다.
- 효과음 1개는 로컬 Agent Audio로 생성하고 앞 타격을 잘라 사용했다. 이벤트별 피치와 음량을 적용하며 M으로 끌 수 있다. [음원 검사](../reports/combat_audio_report.json)는 길이·피크·무클리핑 확인이며 에이전트가 청취 평가한 결과는 아니다.

## 자동 검증과 남은 확인

```powershell
python -m unittest discover -s tests -v
powershell -ExecutionPolicy Bypass -File tools/run_godot.ps1 -Verify
powershell -ExecutionPolicy Bypass -File tools/run_godot.ps1 -RenderCheck
```

- Python 회귀 검사 43개 통과.
- [Godot 규칙 재생](../game/tests/replay_rules.gd): **동일한** [JSON 입력 시나리오](../tests/fixtures/combat_rules.json) 13개·38단계와 소수 유지비 검사를 통과. [보고서](../reports/godot_rules_report.json).
- [전투 통합 검사](../game/tests/smoke_arena.gd): 실제 물리 레이·뷰포트 마우스 입력·이동·HP 피해·사거리·소환 위치·공구 유지/고갈·대체 공격·정지·사망/재시작 등을 검사. [보고서](../reports/godot_smoke_report.json)는 실행 때 갱신된다.
- [누르고 있기 검사](../game/tests/hold_input.gd): 바닥 유지 이동 갱신, 적 위를 지나가도 공격하지 않음, 적 고정 반복 공격과 커서 이탈, 뗄 때 정지, 표적 이동·사망, 모델 전체 선택, 공격 속도에 따른 간격, 동작 중 입력 대기, 우클릭 반복, 토글·소환 키의 단일 시전을 검사한다. [보고서](../reports/godot_hold_report.json).
- [접근 후 시전 검사](../game/tests/approach_cast.gd): 움직이는 적 추적, 기술별 정지 거리, 지면 위치 유지, 시전 시점 비용, 기본 공격 대체 거리, Shift·새 명령·대상 소멸·마나 부족·사망·막힘·재시작을 검사한다. [보고서](../reports/godot_approach_report.json).
- `-RenderCheck`는 실제 GPU로 같은 검사를 실행한 뒤 [화면 PNG](../reports/godot_combat_preview.png)를 갱신한다. 실행 시 잠깐 게임 창이 열린다.

다음은 사용자가 직접 한 판을 플레이하면서 A1~A5의 **조작감·적 접근 속도·마나 답답함·타격음 크기**를 확인하는 것이다. 자동 검사 및 렌더링 검수를 전체 플레이 테스트·최종 밸런스 승인으로 간주하지 않는다. 장애물 내비게이션, 완성 캐릭터 아트, 장비/성장/파밍, 시나리오·허브·대화·커스터마이징 UI는 이번 구현 범위 밖이다.
